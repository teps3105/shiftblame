# sb-report — 外部審計報告

> **sb-think 分發目標**：sb-think 理解老闆要外部審計後分發至此。位置：把當前節點的規格與證據整理成**單一自包含檔案**——外部 agent 讀不到 repo，本報告即其審計所需的全部材料。

當老闆要對當前節點做外部審計（把報告複製給其他無法閱讀原始碼與專案文件的 agent）時執行（由 sb-think 分發）。

先 `load skill: shiftblame`，主對話秘書執行：

## 流程

1. **機械彙整**：跑 `sb report`（SKILL §1.8）——自動產生 `<repo>/.shiftblame/tmp/report-<slug>-<ms>-<node>-<時間戳>.md`，內含：當前節點與推進歷史（含老闆拍板留痕）、審計判準（節點鏈閘門／§10 兩兩一致／四假訊號／測試鎖定）、G1／G2／G3 全文、執行層證據（alignment-check、測試鎖定、build 記錄、驗收報告）、最近 git 記錄。
2. **秘書複核＋補充 §8**：核核對彙整內容與現況一致後，填報告 §8「本次審計問題」——具體指出這次想請外部回答的問題（如「G3 失敗模式是否涵蓋 G2 指出的最大技術風險」「驗收反證嘗試是否足以支撐合格判決」）。沒有具體問題的審計是形式審計。
3. **交付**：提示老闆報告完整路徑，由老闆複製給外部 agent。

## 邊界

- 報告 MUST **自包含**：不得出現「見 repo 某檔」式引用——外部 agent 無法讀取；缺的內容就是缺的審計材料，如實呈現（報告內已標「（尚無…）」）。
- 只讀彙整：不修改任何流程文件、不推進節點、不判決。外部審計結論回來後屬「獨立審核」輸入，由秘書複核承擔責任（SKILL §3），不改變任何閘門義務。
- 對 repo 的讀取與報告產生由主對話秘書執行（§3 承載歸屬）；外部 agent 在 repo 外，只收到本報告。
