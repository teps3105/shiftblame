# 恢復工作

依 [主技能](../shiftblame/SKILL.md) 與 `sb state` 核對 repo、分支及工作樹。使用者已指定工作就接續；插入問題、進度詢問與續行沿用原目標及有效授權。

接續前先完成本對話的產品訪談：新對話寫第一輪，恢復舊對話在同一紀錄末尾追加一輪（觸發寫「恢復對話」）。把交接中的目標、範圍與驗收交使用者重新確認，差異記入該輪；壓縮續接沿用原紀錄，不需重訪。

## 定位與讀取

按 [HANDOFF](../shiftblame/references/HANDOFF.md) 執行 `sb handoff list` 定位具名工作，再以 `sb handoff show <task>` 讀取快照及現況差異。已有明確 task 時直接 show；多個候選才依使用者目標與交接內容選擇，無法辨識時只問必要的目標差異，不以時間最新者冒充正確工作。

沒有具名快照但可能留有舊版 Markdown 交接時，先按使用者回指及既有工作筆記定位 tmp 原稿，核對授權與 Git 現況後再保存為具名 task。保留原稿，不依檔案修改時間自動挑選或把舊筆記直接當成新鮮快照。

## 核對與接續

核對原對話／正式文件中的授權、實際檔案、分支、HEAD、索引及未提交內容。差異是重新判斷證據的線索：保留使用者變更，辨識哪些工作已完成、哪些結果已失效，再修正交接與下一步。分支或 repo 不同時先定位正確工作區；快照不授權切分支、還原檔案或重做已完成工作。

讀取不消耗或刪除快照；必要時以同名 task 保存更新後落點。缺檔、損壞或無法查證時保留原資料及草稿，用正式來源與 Git 重建並按 [save](../save/SKILL.md) 保存，不把舊文字當成已驗證的現況。

從已核對的下一步操作開始，觀察預期結果並持續完成原任務；只有範圍擴大、必要授權與交付確認交使用者判定。
