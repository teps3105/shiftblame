# 保存工作落點

依 [主技能](../shiftblame/SKILL.md) 與 `sb state` 確認 repo、分支、工作樹及最近 commit。交接聚焦下一次要做的事：已授權目標與邊界的來源、已完成／未完成、否決的方案與原因、使用者的原話修正、使用者既有變更、有效及未驗證據、阻塞、下一步操作與預期觀察。已有正式文件、決策及 diff 使用回指；必要技能按讀取順序列出，敏感資料只記取得方式。

## 保存

依 [HANDOFF](../shiftblame/references/HANDOFF.md) 選擇具名 task。先在 tmp 寫交接草稿並核對，再執行 `sb handoff save <task> <草稿.md>`。成功後以 `sb handoff show <task>` 讀回，確認內容及目前差異。

快照在 `.shiftblame/tmp/main/<task>/handoff.json`，包含交接文字與可核對的 Git 定位事實。CLI 不改分支或索引。多個工作分開命名，既有工作更新同名快照。缺 Git 或 CLI 無法查證時保留草稿並揭露未建立正式快照。

保存範圍限於交接本身，維持產品檔案不變。交接記錄不是授權或產品備份；恢復由 [load](../load/SKILL.md) 核對正式來源與實際狀態。保存完成不表示工作已交付，也不自行終止仍可推進的任務。交接是中途保存，不是交付；未完成項由接手者繼續做，不當成建議交回使用者。
