# 恢復工作

依 [主技能](../shiftblame/SKILL.md) 與 `sb state` 核對 repo、工作模式、分支及工作樹。使用者已指定工作就接續；插入問題、進度詢問與續行沿用原目標及有效授權。

## main／直接實作

按 [HANDOFF](../shiftblame/references/HANDOFF.md) 執行 `sb handoff list` 定位具名工作，再以 `sb handoff show <task>` 讀取快照及現況差異。已有明確 task 時直接 show；多個候選才依使用者目標與交接內容選擇，無法辨識時只問必要的目標差異，不以時間最新者冒充正確工作。

沒有具名快照但可能留有舊版 Markdown 交接時，先按使用者回指及既有工作筆記定位 tmp 原稿，核對授權與 Git 現況後再保存為具名 task。保留原稿，不依檔案修改時間自動挑選或把舊筆記直接當成新鮮快照。

核對原對話／正式文件中的授權、實際檔案、分支、HEAD、索引及未提交內容。差異是重新判斷證據的線索：保留使用者變更，辨識哪些工作已完成、哪些結果已失效，再修正交接與下一步。分支或 repo 不同時先定位正確工作區；快照不授權切分支、還原檔案或重做已完成工作。

讀取不消耗或刪除快照。main 沒有活動階段與 `last_save`，沿目前已授權工作接續；必要時以同名 task 保存更新後落點。缺檔、損壞或無法查證時保留原資料及草稿，用正式來源與 Git 重建並按 [save](../save/SKILL.md) 保存，不把舊文字當成已驗證的現況。

## 活動 slug

核對 slug／ms、階段及已核准契約，讀取相關正式文件。活動 slug 優先於舊 main 快照，不藉恢復切換流程。

有 `last_save` 時，讀 SLUG §8 指向 tmp 內的交接，核對實體路徑、commit、狀態與目前差異。成功才清除標記；缺檔、越界或矛盾時保留標記，由現有文件及 git 重建落點。重建後依 [save](../save/SKILL.md) 保存。

無交接時按原階段讀取已存在且適用的 G 檔與證據。保留仍有效的工作，修正過時技術描述；G1 定義偏離封存時先查明差異，需求改義仍須重新核准。

從已核對的下一步操作開始，觀察預期結果並持續完成原任務；只有範圍擴大、必要授權與既有決策時點交使用者判定。
