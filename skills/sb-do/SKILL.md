# sb-do — 確認完稿，放行進入開發

> **sb-think 分發目標**：sb-think 理解老闆要放行開發後分發至此。位置：三面向制衡完成、§10 一致 → 放行進入開發。

當老闆要放行開發時執行（由 sb-think 分發）。用於三面向制衡完成、老闆確認完稿後，放行進入開發。

先 `load skill: shiftblame`，主對話秘書執行：

## 流程

0. **秘書核對 §10 一致性**（主對話）：讀取當前 `<nnn>` 的 G1／G2／G3，親自核對兩兩雙向一致（三對六向）。**M 級（§0.1）免此步**——M 級只有 G1 單份，不核 §10。
1. **放行判定**：
   - **L 級**：**三對六向全成立** + 審計、規劃階段已透過秘書代派子代理複核對應外部獨立研究（結論存 `tmp/`）；研究階段由主對話自行派發探索子代理（§3 承載歸屬） → 放行。SLUG §4 節點從 `三面向制衡（G1↔G2↔G3）` 推進到 `開發`。
   - **M 級**：G1 單份定稿（需求＋驗收項完整、與 sb-think 對齊的意圖一致）→ 放行。SLUG §4 節點同樣推進到 `開發`；不要求 G2/G3 與 §10。
   - **任一向缺漏**（L 級）→ **拒絕放行**，提示具體缺漏（如「G2 §1 技術分析未回指 G1 需求 R3」），要求對應階段調整自己文件後重核。
   - 外部獨立研究未取得（L 級）→ **不得放行**（文件不得定稿，SKILL §3）。
2. **放行後進入開發**：主對話秘書依 G3 實作計畫採多循環螺旋開發（§1.4），推進**執行層時序**執行觸發重流程條件的功能（commit 單位）；**每個 nnn 就是一個里程碑**（G3 §1.5 定義本 nnn 功能範圍，L 級）。**預設直接修正**：功能未觸發 §1.4 重流程條件（① 行為改變 ② 介面改變 ③ 多檔協同 ④ 跨層級 ⑤ 老闆指定）時，秘書直接執行並 commit，不走執行層時序。觸發時走執行層鏡像時序：測試階段（子代理）寫測試定義「過」（依 G3）→ 開發階段（**主對話**，依 G2）寫實作碼＋實機驗證 → 驗收階段（子代理）跑 CI 測試、驗收「完成」（對照 G1）→ 秘書讀 `tmp/` 三份產出後**判決合格才 commit（獨佔）**；判決含**測試真實性檢查**——無真實斷言的假測試判返工回測試階段（SKILL §1.4）。**測試先行**：先寫測試（紅燈）再實作，與定義層「驗收先於實作」對齊。本 nnn 所有功能 commit 完成後觸發收斂（M 級無里程碑：單循環後即收斂）。**commit 與所有判決（合格/返工）由秘書獨佔**；執行層中測試/驗收性質子代理可在授權範圍內寫 repo（測試寫測試碼、驗收寫測試環境配套並跑 CI 測試）但皆不可 commit，**開發階段（G2 落地）由主對話親為**（§3 承載歸屬）；定義層中審計/規劃性質子代理對 repo 唯讀，**研究階段（G2）由主對話親為**。

## 邊界

- 本 prompt 是**放行 gate**，不產出新文件、不改需求；只核對既有 G1~G3 一致性並推進節點。
- 一致性核對以 §10 為唯一判準；不得以「看起來一致」繞過逐項核對。
- 放行後進入開發；開發中發現問題，依「常態修正 vs 重大例外」（§1.4）處理——重大方向變更走重大例外遷移退回對應面向（§1.4.1）。
