# shiftblame:rewrite — 返工重寫為當下事實

> **shiftblame:think 分發目標**：回退修正或重走 intent 開新輪後整理各段成果、或老闆點名整理治理文件時的分發執行紀律。位置：不開新寫入權、不改節點——重寫發生在寫入矩陣既有的段位窗口內，本技能承載「怎麼重寫」的操作紀律。

G1~G3 與 SLUG 的讀者是**下一輪的 agent 與老闆**：讀到的必須是「現在有效的契約與狀態」，不是「曾經發生過什麼」。返工後逐步追加條目、並列新舊版本、留下歷史標記，會讓治理文件淪為補釘串接、前令壓後令——每次返工都讓文件更長、更難讀、更無法辨識當下事實。時序（哪一輪改了什麼）由 flow-state history＋輪次計數承擔；回退修正依主技能 A4 決定工作段，本技能承載成果如何保持當下自洽。

**機械承載（hooks 載入閘——不靠自發）**：修正輪（`sb next intent` 後 rev 有值）寫 G1~G3.md 時，hooks 機械驗證本輪已調用過 `shiftblame:rewrite`（Skill 調用記 `rewriteSeen.rev`，比對當前 rev）——未載入即擋寫入並要求先調用；載入一次後本輪全放行，下一輪重新驗。`sb next intent` 的修正輪訊息會同步提示。天花板如實：閘面＝整檔（hooks 無檔內分區粒度）、非 archive；SLUG.md 不在此閘（秘書層恆可寫——SLUG 收斂紀律由技能承載）；Bash 內直寫 G 檔不在此層（同寫入矩陣殘餘面）；自調 hooks 偽造調用事件可自鑰匙、調用≠消化（同 externalEvidence 天花板——抽查承擔）。

先 `load skill: shiftblame`，主對話秘書執行：

## 流程

0. **觸發識別**（主對話）：返工態（verify fail 回指、任意節點重走 intent 開新輪、出口後追加擴充 G1）重走流程時；或老闆點名整理已堆疊的存量治理文件時。存量整備依 A4 回責任段修正，不另開寫入窗口（寫入權綁段位，矩陣不變）。
1. **重寫前裁定歷史去向**：`.shiftblame/` 不入 git——「歷史不可變性由 git 承擔」對 G/SLUG 內容不成立，重寫即銷毀。舊輪內容預設銷毀（時序已有 flow-state history 承擔）；判定需要跨輪對照脈絡時，先傾倒 `<repo>/.shiftblame/tmp/<slug>/` 再重寫。不逐輪歸檔、不建立版本副本——那只是把堆疊換個地方重演。
2. **定義區整檔重寫**（定義段內）：requirement 段以新契約**全量重寫** G1 定義區，research／plan 段對齊新 G1 全量重寫 G2／G3 定義區。重寫＝重看每一條、重評估、重設計：既有條目逐條裁定三態——納入（改寫或維持）或淘汰（刪除），不存在「留著參考」。產出必須讀起來像**第一次就寫成**的自洽版本：無「修正後」「r02 改為」「本輪新增」等歷史標記殘留，無同義條目並列，無已被新輪取代的舊行文——歷史標記的資訊屬 flow-state 與 commit 訊息層。
3. **回指區同鍵覆寫**（落地段內）：test 回指 G3、build 回指 G2、verify 回指 G1 時，**以鍵覆寫，不逐輪追加**——G1 回指區以 AC-ID 為鍵（同 AC 的新判定覆寫原行）、G2 回指區以 T-ID 為鍵（同 T 的新結果覆寫原行，偏離欄位隨行收斂）、G3 回指區以 AC-ID 排程行為鍵。新鍵（新 AC／新 T／新偏離）＝新事實，正當新增；同鍵多行列並存＝堆疊，病。
4. **SLUG 收斂**（ms 出入口）：§4 段表**更新原列**、定案索引**以 `<nnn>` 為鍵覆寫原行**——不追加同 ms 重複列。SLUG 各段語義不同，重寫紀律只落在此類既有覆寫語義的段（§4 段表、定案索引、收斂執行記錄）。
5. **自檢**：重寫後逐檔回讀——每個段落是否當下事實的唯一表述？同鍵是否單行？歷史標記是否殘留？不通過即再重寫，不以「補一段說明」收尾。

## 邊界

- **寫入權與段位不變**：重寫只發生在寫入矩陣既有的段位窗口（G1 定義區＝requirement 段、G2＝research、G3＝plan；回指區＝各自落地段；SLUG 恆可寫）。本技能是執行紀律載體，不是隨時叫出來全檔重寫的工具——機械承載只有載入義務閘（返工輪 hooks 驗本輪已調用本技能後才放行 G 檔寫入，見上「機械承載」），寫入權與段位零變更。
- **SLUG 排除段**：§1 老闆原始命題忠實承載、不重寫（重寫＝篡改審計源頭）；§3 待辦、§6 技術債、§7 租約是設計上累積的段——技術債／租約失效時**標記處置**，不抹除歷史項。
- **SOP／ROADMAP 不在打擊面**：永續層文件由專屬 sopreview 迴路承載（每 ms 三問＋機械基本功），不經本技能。
- **框架 repo 自身文件不在打擊面**：框架演化文件的「僅追加零刪改即擋」鐵律由 hooks 承載，與本技能分屬兩層。
- **辨識基準**：「追加」本身不是病——新 AC、新 T、新 ms 定案是新事實的正當增長；病是**同一事實的多版本並存**（同鍵堆疊、新舊並列、歷史標記殘留）。裁定基準永遠是「這一條是否仍在當下有效的事實表述」，不是「這一條是否曾被寫過」。
