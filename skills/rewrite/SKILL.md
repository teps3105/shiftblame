# 重整參照文件

文件大幅改動時，先保存來源，再依讀者任務重整。依 [主技能](../shiftblame/SKILL.md) 的授權邊界與專案規範作業。一般小幅修正可直接編輯。

## 保存與更新

1. 執行 `sb rewrite` 保存根 README、`docs/` 及框架本機文件的現有快照，核對輸出路徑。其他必要來源另行保存，保護未入庫材料。
2. 確定讀者要完成的工作，核對現有內容、來源與實際行為。
3. 依範圍更新文件。大綱仍適用時沿用；需要重組時重寫。標題序列變化不代表品質改善。
4. 回讀改動及直接依賴，核對引用、命令與事實，執行專案適用檢查。

`sb rewrite` 預設提供快照，不強制文件編號、層級、索引名稱、文風或重排。顯式啟用的外部政策可加入檢查。入口見 [MECHANISMS](../shiftblame/references/MECHANISMS.md)。

## 回讀

依 [DOCS](../shiftblame/assets/DOCS.md) 核對正確性、可理解性與操作用途。事實須有權威來源，術語須能由讀者理解，失效描述應更新。歷史留 Git；尚未採用的提案保留提案身分。未驗項先補驗；交付時指出有效文件位置，只有被停止條件擋住的才寫明沒驗的項目與卡點。
