# G3 — 驗收出口

## 正方：驗收審計

> 依 G1.md 與 G2.md 成果，定義 GWT 驗收條件寫入 G3.md。

**職責**：限業務邏輯 GWT ＋唯讀產品驗證。R1 讀取 G1+G2 全部產出。
**驗證動作限三類**：(1) 執行既有測試套件（含 G2 正方撰寫的測試）(2) 操作 UI 觀察行為 (3) 發送 HTTP 請求觀察回應。
**禁止**：修改任何檔案。G3 角色純唯讀驗證。
**盲獨立原則**：各子代理間不共享上下文、不互看產出。管理者綜合收斂為 G3.md 正方提出段。
**子代理上下文**：角色：驗收提出者 | 任務：G1.md + G2.md | 背景：REPO/ROADMAP | 讀寫：UTF-8
**產出格式**：產出模板見 TEMPLATES/SLUG.md。GWT 格式：`G<N>: 標題 — Given/When/Then — 對應計畫項`。

## 反方：驗收質疑

> 多子代理全域質疑，揭露風險供老闆參考。禁止使用 PASS/FAIL。

**質疑方向**：(1) 覆蓋率：GWT 是否涵蓋 G1.md 所有變更 (2) 純業務性：是否混入技術細節 (3) 一致性：產物間邏輯自洽 (4) 落地可行性。禁止：不審實作品質、不審計畫方向。
**驗證授權**：反方可執行與正方相同的唯讀驗證動作，用於質疑覆蓋度。同受「禁止修改任何檔案」約束。
**技術/業務判準**：What=業務、How=技術。否定判準：涉及檔案路徑/函式簽名/資料結構/演算法者為技術。正方 GWT 混入 How 時標註為風險。
**盲獨立原則**：各子代理間不共享上下文、不互看產出。管理者綜合收斂為 G3.md 反方質疑段。
**質疑標註**：力度 HIGH/MEDIUM/LOW。審計分類：符合/缺失/改善（非 PASS/FAIL 判定）。
