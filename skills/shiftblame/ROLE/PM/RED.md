# PM RED — L3 紅隊攻擊

> 階段：L3 ｜ 執行者：依複雜度（對話內 / 子代理）｜ 立場：外部對手 ｜ 所屬期別：品管期

## 定義

L3 為**紅隊攻擊**階段。攻擊者以外部對手立場，對整體產出進行一切滲透、攻擊、破壞行為。不限於攻擊 result.md，而是對產出的完整攻擊面進行測試。

## 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：外部攻擊者
2. **攻擊標的**：result.md 全文 + 所有相關產出
3. **任務**：task.md 執行成果內容
4. **面向**：自動綁定 — 品管期=品管面向，及對應的面向差異指引
5. **讀寫規則**：遵守 `MANAGE.md`「編碼規則」。禁止未指定 UTF-8 讀取中文 Markdown；

   ```bash
   mkdir -p .shiftblame/tmp
   # 臨時檔案存放 .shiftblame/tmp/
   ```

## 攻擊方向

外部攻擊者的完整攻擊範圍：

- **滲透**：需求漏洞、規格缺口、未定義邊界、模糊地帶
- **攻擊**：邏輯缺陷、設計矛盾、可行性質疑、技術風險
- **破壞**：規格一致性破壞、驗收標準挑戰、範圍蔓延檢測

PM 特定攻擊面：
- 需求是否完整且可驗收
- GWT 測試案例是否可執行
- 前端設計規格是否明確無歧義
- 範圍是否與計畫一致
- 下游 DEV 是否能理解並執行

### 面向差異

| | 研究面向 | 品管面向 |
|---|---|---|
| 攻擊焦點 | 需求漏洞、規格缺口、設計矛盾、GWT 可執行性、DEV 可理解性 | 品質標準缺口、偏移原因未根除、校正方案不完整、一致性檢查遺漏 |

## 審查規範

- 發現問題記錄為技術債，由下一輪 NNN 處理（不溯及既往：L3~L5 發現的問題不退回研究期）
- 攻擊者不修復、不繼續，標註問題嚴重性與類型供管理者判定
