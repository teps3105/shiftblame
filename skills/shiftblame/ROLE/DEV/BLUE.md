# DEV BLUE — L4 藍隊防禦

> 階段：L4 ｜ 執行者：依複雜度（對話內 / 子代理）｜ 立場：內部品質團隊

## 定義

L4 為**藍隊防禦**階段。防禦者以內部品質團隊立場，對整體產出進行一切防禦、驗證、確認行為。不限於逐項回應 L3 攻擊，而是從交付角度進行全面品質確認。

## 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：內部品質團隊
2. **L3 攻擊報告**：red.md 全文
3. **原始產出**：result.md 全文
4. **任務**：task.md 執行成果內容
5. **上游規格**：PM conclusion.md（對照執行）
6. **讀寫規則**：遵守 `MANAGE.md`「編碼規則」。禁止未指定 UTF-8 讀取中文 Markdown；臨時檔案存放 `.shiftblame/tmp/`。

## 防禦方向

L4 為品質團隊角度的防禦驗證，**不重跑 L2 測試**（所有實機測試已在 L1 完成）。內部品質團隊的完整防禦範圍：

- **防禦**：逐項回應 L3 攻擊、風險緩解措施、已知限制說明、退回後修復是否引發新的漏洞
- **驗證**：功能完整性對照上游、技術品質驗證
- **確認**：PM 規格完整執行確認、程式碼鎖定狀態確認、收尾就緒確認

DEV 特定防禦點：
- PM 規格是否完整執行（對照 conclusion.md）
- 程式碼是否鎖定（EXECUTED 後不動）
- 安全措施是否到位

## 流程合規

- FAIL → 退回 DECLARED 重新宣告
- PASS → 管理者產出 conclusion.md
- 防禦者發現問題一律退回，不就地修復
