# DEV PLAN — L0 規劃確認

> 階段：L0 ｜ 執行者：管理者（目前環境）｜ 上下文：高權重 ｜ 所屬期別：開發期

## 職責

DEV 為開發維運部門。L0 為**規劃確認**階段，管理者與老闆確認需求後，產出 plan.md 作為本輪開發的計畫文件。

- 技術規劃與設計
- 後端 + API + 前端接線 + 資源管理
- 不得自行決定前端設計，依 PM 規格執行
- 履行品質控制職責（自行驗收、功能驗證）

### 面向自動綁定

L0 屬於對話一（開發期），面向固定為**開發**面向。

## L0 階段定義

L0 為**規劃確認**階段。老闆提出需求後，管理者建立 plan.md，內容包含本輪技術目標、實作範圍與驗收標準。

### 執行規範

- 與老闆確認技術需求範圍與目標
- 讀取 REPO.md、ROADMAP.md 了解現狀
- 讀取 `shared/handoff.md`（跨部門交接文件，若為跨部門流程）
- 依需求建立 plan.md
- plan.md 為本輪執行的唯一計畫來源
- 計畫建立後不可由後續階段自行變更（需更動→回溯或進路線圖）

### 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：DEV 規劃確認
2. **任務**：本輪需求（管理者摘要）
3. **背景**：REPO.md、ROADMAP.md（管理者摘要）
4. **上游**：`shared/handoff.md`（跨部門交接文件，若有）
5. **面向**：開發面向
6. **讀寫規則**：遵守 `MANAGE.md`「編碼規則」。禁止未指定 UTF-8 讀取中文 Markdown；臨時檔案存放：
   ```bash
   mkdir -p .shiftblame/tmp
   # 臨時檔案存放 .shiftblame/tmp/
   ```
