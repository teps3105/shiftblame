# DEV TASK — L1 執行任務

> 階段：L1 ｜ 執行者：依複雜度（對話內 / 子代理）｜ 上下文：見 MANAGE.md ｜ 所屬期別：開發期

## 職責

DEV 為開發維運部門。跨部門流程（PM→DEV）時上游為 PM；單獨執行時無上游。面向自動綁定：開發期（L0~L2）= 開發面向、維運期（L3~L5）= 維運面向。

- 技術規劃、設計、執行
- 後端 + API + 前端接線 + 資源管理
- 不得自行決定前端設計，依 PM 規格執行
- 履行品質控制職責（自行驗收、功能驗證）

### 面向差異

| | 開發面向 | 維運面向 |
|---|---|---|
| 觸發時機 | 技術實作、程式碼變更、功能開發 | 開發完成後使用者視角維運、端到端驗收 |
| L1 重點 | 程式碼實作、技術設計、API 開發、前端接線 | 使用者視角功能維運、端到端流程測試、使用者體驗品質確認、異常情境覆蓋 |
| 產出特徵 | 程式碼變更、技術文件、測試覆蓋 | 使用者維運報告、端到端測試結果、使用者體驗評估 |
| 驗收標準 | 功能實作完整、GWT 逐條通過、技術品質達標 | 使用者視角功能正確、端到端流程完整、使用者體驗品質達標 |
| 攻擊焦點 | 程式碼缺陷、安全漏洞、效能瓶頸、PM 規格未完整執行 | 使用者視角遺漏、端到端流程斷裂、異常情境未覆蓋 |
| 防禦焦點 | 技術品質防禦、規格執行完整性、程式碼鎖定狀態 | 使用者維運完整性、端到端正確性、使用者體驗品質 |

## L1 階段定義

L1 為**執行任務**階段。宣告通過後，執行者直接執行所有產出。

### 執行規範

- 依本輪計畫執行所有產出（程式碼實作、文件修改、測試撰寫等）
- 依 `shared/handoff.md`（跨部門交接文件）定義本輪可見功能
- 建立技術前置內容
- GWT 逐條跑通
- commit 格式：
  ```bash
  git add -A
  git commit -m "<type>(<slug>): <繁體中文標題>"
  # <type> 為 feat / fix / chore 等
  ```
- 計畫不可更動（已 PASSED 的前輪計畫範圍不得變更）
- **所有測試在 L1 完成**：GWT 逐條驗證、邊界測試、端到端實機驗收。L4 不重跑測試，僅做品質團隊角度的防禦驗證
- 程式碼執行完成後 commit：
  ```bash
  git add -A
  git commit -m "feat(<slug>): <繁體中文標題>"
  ```
  進入 L2 驗收
- 程式碼 EXECUTED 後鎖定，L3~L5 期間不得修改；不溯及既往：L3~L5 發現的問題記錄為技術債，由下一輪 NNN 處理

### 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：DEV 執行者
2. **任務**：本輪計畫（管理者摘要）
3. **背景**：REPO.md、ROADMAP.md（管理者摘要）
4. **上游**：`shared/handoff.md`（跨部門交接文件，下游必讀）
5. **面向**：面向自動綁定 — 開發期（L0~L2）= 開發面向、維運期（L3~L5）= 維運面向
6. **讀寫規則**：遵守 `MANAGE.md`「編碼規則」。禁止未指定 UTF-8 讀取中文 Markdown；臨時檔案存放：
   ```bash
   mkdir -p .shiftblame/tmp
   # 臨時檔案存放 .shiftblame/tmp/
   ```
