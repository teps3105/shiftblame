# DEV DEFEND — L4 內部驗證

> 階段：L4 ｜ 執行者：依複雜度（對話內 / 子代理）｜ 立場：內部品質團隊

## 定義

L4 為**內部驗證**階段。驗證者以內部品質團隊立場，對整體產出進行一切防禦、驗證、確認行為。不限於逐項回應 L3 攻擊，而是從交付角度進行全面品質確認。

## 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：內部品質團隊
2. **L3 攻擊報告**：red.md 全文
3. **原始產出**：result.md 全文
4. **任務宣告**：task.md 宣告內容
5. **上游規格**：PM conclusion.md（對照實作）
6. **讀寫規則**：同 EXECUTE.md

## 驗證方向

內部品質團隊的完整驗證範圍：

- **防禦**：逐項回應 L3 攻擊、風險緩解措施、已知限制說明
- **驗證**：功能完整性對照上游、GWT 全部通過、技術品質驗證
- **確認**：PM 規格完整實作確認、程式碼鎖定狀態確認、收尾就緒確認

DEV 特定驗證點：
- PM 規格是否完整實作
- GWT 是否全部通過
- 程式碼是否鎖定（EXECUTED 後不動）
- 安全措施是否到位

## 流程合規

- FAIL → 退回 DECLARED 重新宣告
- PASS → 管理者產出 conclusion.md
- 驗證者發現問題一律退回，不就地修復

## blue.md 產出格式

```markdown
# 內部驗證報告 — <slug> DEV/<NNN>

## 驗證摘要

（驗證者填入整體評估）

## L3 攻擊回應

### D1: 回應 A1 — （攻擊點標題）
- **判定**：同意修正 / 不同意 / 可選改善
- **回應**：（回應理由）
- **行動**：原地修正 / 不修正

## 驗證項目

### V1: （驗證項目標題）
- **類型**：防禦 / 驗證 / 確認
- **結果**：通過 / 未通過
- **說明**：（驗證說明）

## 結論

PASS / FAIL
```
