# DEV RED — L3 紅隊攻擊

> 階段：L3 ｜ 執行者：依複雜度（對話內 / 子代理）｜ 立場：外部對手 ｜ 所屬期別：維運期

## 定義

L3 為**紅隊攻擊**階段。攻擊者以外部對手立場，對整體產出進行一切滲透、攻擊、破壞行為。不限於攻擊 result.md，而是對產出的完整攻擊面進行測試。

## 子代理上下文需求

若判定為高複雜度需開子代理，派工 prompt 必須提供：

1. **角色**：外部攻擊者
2. **攻擊標的**：result.md 全文 + 所有相關產出
3. **任務**：task.md 執行成果內容
4. **上游規格**：`shared/handoff.md`（跨部門交接文件，對照執行）
5. **面向**：面向自動綁定 — 開發期（L0~L2）= 開發面向、維運期（L3~L5）= 維運面向
6. **讀寫規則**：遵守 `MANAGE.md`「編碼規則」。禁止未指定 UTF-8 讀取中文 Markdown；臨時檔案存放：
   ```bash
   mkdir -p .shiftblame/tmp
   # 臨時檔案存放 .shiftblame/tmp/
   ```

## 攻擊方向

外部攻擊者的完整攻擊範圍：

- **滲透**：功能漏洞、邊界遺漏、未處理的邊角案例、安全盲點
- **攻擊**：邏輯缺陷、技術品質、效能瓶頸、架構弱點
- **破壞**：上游功能未執行、GWT 未通過、前端未遵循 PM 規格、程式碼品質破壞

DEV 特定攻擊面：
- 上游 PM 規格是否完整執行（對照 `shared/handoff.md`）
- GWT 是否全部通過
- 技術選型是否合理
- 安全性、效能、程式碼品質
- 前端是否遵循 PM 規格

### 面向差異

| | 開發面向 | 維運面向 |
|---|---|---|
| 攻擊焦點 | 程式碼缺陷、安全漏洞、效能瓶頸、架構弱點、PM 規格未完整執行 | 使用者視角遺漏、端到端流程斷裂、異常情境未覆蓋、使用者體驗品質不足 |

## 審查規範

- 不溯及既往：L3~L5 發現的問題記錄為技術債，由下一輪 NNN 處理
- 攻擊者不修復、不繼續，標註問題嚴重性與類型供管理者判定
