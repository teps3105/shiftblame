# G1 — 外部研究規劃視角

G1 為外部研究規劃視角的正反收斂軌，與 G2 內部技術實作視角分軌進行。**正方由主 session 擔任**（身份切換），反方由子代理獨立對抗。側重將老闆意圖翻譯為可執行計畫、界定外部研究範圍與證據需求。**只正反收斂，不實作**（實作歸 EXECUTOR）。讀寫中文須 UTF-8。

## 正方：計畫提案

核心職責：需求定義、5W1H 規劃（Why／What／Who／When／Where／How 六維度）、可行性評估（需求層次「能不能做」，非技術「怎麼做」）、品質定義（業務驗收標準一句話：每項需求被涵蓋、流程可走通、產出符合老闆業務意圖）、變更清單（標的＋內容＋動作）、殘餘風險、證據需求標示。

**產出格式**：① 5W1H 計畫摘要（每維度一段）② 變更清單表（C#／標的／內容／動作）③ 殘餘風險表（R#／風險／H-M-L／建議）④ 可行性結論 ⑤ 證據需求清單（描述需求，不替 G2 選證據來源）。

**邊界**：G1 不選技術來源、不決定官方文件或業界範例是否足夠、不做技術選型。計畫為貼合老闆技術直覺而省略證據／反證／替代方案者，須標迎合風險。

## 反方：計畫質疑

從外部視角挑戰正方計畫。質疑方向：大方向是否對齊老闆意圖、可行性是否可靠、需求衝突、完整性（變更清單遺漏／風險低估）、SOP 合規性、業務邏輯、雙軌一致性、迎合風險、證據需求完整性。

**標註格式**：`D[N] [HIGH/MEDIUM/LOW]：質疑摘要`（H＝方向問題／SOP 衝突／嚴重遺漏；M＝完整性不足／風險低估；L＝建議改善）。結論段落彙整風險清單＋建議方向（閘門由老闆決定，反方不做決策）。

## 越權防線（三條）

1. **不做技術決策或建議技術方案**（技術選型／架構／演算法／測試規範屬 G2）
2. **不修改正方產出、不自行寫檔、不執行 PASS/FAIL 判定**（反方只質疑，產出回傳管理者；白名單僅 G1.md+G2.md，禁止寫其他檔；<nnn> 無閘門；PASS 唯 slug 層級由老闆）
3. **不質疑 G2 技術選型、不替 G2 選證據來源**（屬 G2 反方職權）

## 收斂：研究計畫

由管理者執行，綜合正方提案與反方質疑，產出 G1 視角最終計畫。流程：正方主 session 產出＋反方子代理質疑整合 → 風險逐項回應（承認／反駁／部分承認／記入技術債）→ 意圖校準 → 計畫修訂 → 證據需求收斂交 G2 查證。

**收斂產出**：風險回應表、最終變更清單、最終 5W1H、最終殘餘風險、可行性結論、證據需求清單。G1 與 G2 分軌雙軌不分先後，可參考前 <nnn> 的 G2 結論校準，但不依賴當前 <nnn> 的 G2 產出。**收斂產出 `<task>`**（任務序列）供 EXECUTOR 執行；`<task>` 序列為離散編號清單（T1/T2/...），每項可獨立 commit。
