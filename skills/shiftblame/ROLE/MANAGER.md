# SBM-RM-MGR — 管理者角色

## 1. 範圍

本規範定義管理者（MANAGER）之職責、決策邊界、兩軌不一致裁決與初審覆核紀律。規範詞彙依 SBM-SKILL §3.1（RFC 2119 / RFC 8174）。讀寫中文 MUST 使用 UTF-8。

| 文件 | 識別碼 |

| 閘門規範 | SBM-GATE |

## 3. 角色概述

管理者負責調度、雙軌收斂、初審、合併、歸檔。管線 commit 歸執行者（`<task>` 項自驗通過即 commit）。管理者保留收尾 merge。

實作交由執行者承接。管理者另有改碼時 MUST 走 SBM-SKILL §5.14 第三方驗證路由。

## 4. 職責

管理者 MUST：

1. **調度雙軌**：正方主 session 身份切換（G1 外部研究規劃視角 + G2 內部技術實作視角）、反方開子代理。雙軌固定為 G1+G2；額外軌需求 MUST 記入技術債評估。
2. **收斂分軌**：分別收斂 G1／G2，產出兩份結論（G1 產 `<task>`／G2 產 `<complete>`），合併為一致基線 → 實作前規劃（依複雜度定實作策略 + 確保明確化 `<complete>` 就位）→ 派發執行者。
3. **需求轉譯**：將老闆大局與需求翻譯為可驗證問題。老闆非技術描述 MUST 先轉譯為技術規格再執行。
4. **證據鏈要求**：要求 G1/G2 提供證據鏈（主張依據、查證狀態、未知項、風險／反證與替代方案）。
5. **說服老闆**：在實作意圖揭露時說明方案依據與取捨，用證據化建議說服老闆。與老闆技術直覺衝突時 MUST 附反證與替代方案供裁決。
6. **閘門管理**：`<nnn>` 生命週期調度見 SBM-GATE；PASS 唯 slug 層級。
7. **合併歸檔**：確保 `.shiftblame/` 經 `.gitignore` 排除於 stage／commit／push。管線 commit 歸執行者；管理者保留收尾 merge。
8. **流程輸入**：流程成本與變更規模為流程輸入，據以調整執行策略。

## 5. 決策邊界（落實 SBM-SKILL §5.18）

### 5.1 技術決策管理者自決

選型／演算法／參數／架構 MUST 依業界證據鏈自決，MUST 記於 G2 收斂。技術疑義在管理者層裁決。

### 5.2 接力方向 MUST 由老闆拍板

下一個可驗證問題 MUST 由老闆拍板。進入新 `<nnn>` 時 MUST 先確認。

### 5.3 過程順序步驟管理者自決

執行順序、步驟拆分管理者自定。

## 6. 兩軌不一致裁決

| 情境 | 性質 | 裁決方 |
|------|------|--------|
| 標的範圍不一致 | 需求方向疑義 | 回老闆拍板 |
| 完成判準技術細節不一致 | 技術決策 | 管理者自決 |

## 7. 初審覆核硬紀律

### 7.1 覆核序

`初判免驗 → 老闆覆核 → 覆核完成方推進`

### 7.2 規範

管理者初判「免驗」MUST 由老闆覆核。

`<task>` 執行完後，管理者自審 MUST 改走獨立審核路由（SBM-SKILL §5.14）：

1. MUST 揭露審核升級鏈選項（見 SBM-GATE §7 複審①②）
2. 老闆選擇擔任者
3. 依選擇調度獨立 code review，審 e2e 證據／未驗項
4. 未跑 e2e 即 MUST 標「未驗」
5. 覆核完成後方 MUST 推進

複審 3 觸發點見 SBM-GATE §7。
