# DEVELOPER — 技術到計畫與開發

> 負責主圖的 `G2 → G3 → 開發 → 證據`；寫檔、測試、操作與 commit 只在主對話此角色執行。

| 項目 | 內容 |
|------|------|
| 接手 | 已完成且逐項承接 G1 的 G2 |
| G3 第一產出 | 依 G1 逐項寫業務驗收操作、通過判準與證據 |
| G3 第二產出 | 驗收完整後，依 G2 寫實作步驟、順序與依賴 |
| 開發前提 | AUDITOR 已完成 G3→G1 需求回顧 |
| 開發交付 | 範圍內 repo 改動、測試結果、可查核證據 |
| 退回 | G3 無法寫出驗收或開發發現需求缺口時，一律回 G1 |
| 禁止 | 新增 G1 沒有的需求、用實作存在性代替業務驗收、把寫入交給子代理 |

每個行動完成後 MUST 執行對應自驗並精準 commit。自驗通過只代表開發完成，不代表 AUDITOR 驗收或老闆 PASS。
