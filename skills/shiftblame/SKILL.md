# shiftblame — AI Agents 協作框架

正反回饋迴圈框架。會話由老闆自由管理。

1. **回饋即意圖**：老闆回饋為意圖確認素材，不可直接執行，禁止寫入記憶
2. **SOP 紀律**：可更新 SOP 作為全局標準，建立與修改皆需意圖揭露
3. **PRD/PID 筆記本**：老闆的筆記本，agent 可參考與協助整理，不進 slug 鏈
4. **先提出再質疑**：正方提出→反方質疑，四行為（計畫/開發/驗收/辯論）各 2 輪正反迴圈
5. **迭代收斂**：行為出口 FAIL 回同行為重計數（R2 產出為起始基線，覆寫不重建）
6. **Shift Blame**：閘門 PASS 前老闆的鍋；閘門 PASS 後 agent 的鍋

## 啟動序列

每次觸發**僅載入索引層**，禁止一次讀入整個專案。依序：
1. **未歸檄偵測**：掃描 `.shiftblame/` 下未歸檔 SLUG.md
2. **四文件載入**：REPO.md → ROADMAP.md → SOP.md → GRAPH.md
3. **Repo 狀態**：git log、status、branch
其餘依需求按需載入。

## 觸發

| 觸發方式 | 行為 |
|---------|------|
| `/shiftblame <任意文字>` | 意圖線索 → 啟動序列 → 呈現意圖 → 確認 → 分流 |
| `/shiftblame`（有未歸檔） | 啟動序列 → 呈現清單 → 老闆選擇 → 分流 |
| `/shiftblame`（無未歸檔） | 啟動序列 → 提議 slug → 確認 |
| slug 確認後 | 管理者掃描環境 → 提出子代理策略 → 啟動計畫行為 |
| 驗收 PASS 後 FAIL | 自動觸發 → 同 slug 開新 NNN |

意圖揭露詳 GATE.md。觸發後不直接執行；呈現意圖時**必須包含執行模式**（slug 流程 vs main 直接執行），由老闆決定。

## 模式

四行為迴圈：**計畫**→ **開發**→ **驗收**→ **辯論**（DEBATE 正方→OBJECTION 反方）。每行為恰好 2 輪正反交替（R1 正→R1 反→R2 正→R2 反）。計畫/驗收/辯論行為正方為多子代理盲獨立；開發行為正方由管理者視情況決定子代理策略。反方皆為質疑者。辯論行為為 G3 PASS 後強制觸發，不需觸發表記載。

## 閘門

閘門：計畫出口 → 開發出口 → 驗收出口 → 辯論出口
四行為四斷點：每行為 R2 反完成後，必須老闆確認通過才進入下行為。辯論行為為驗收 PASS 後自動進入（強制觸發）。行為內部 R1↔R2 自動推進不需閘門。
分支：同 slug 使用 `feat/<slug>` 分支，agent 禁止直接操作 main。

## 角色與定義檔

八角色：正方（PLAN/TASK/RESULT/DEBATE）提出、反方（RED/BLUE/CONCLUSION/OBJECTION）質疑。詳見 `ROLE/`；閘門/收尾→GATE.md；管理者→MANAGE.md；模板→TEMPLATES/；工具→TOOLS/
