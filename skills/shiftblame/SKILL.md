# shiftblame — 回饋驅動的 agent 協作框架

> All you need is feedback.
> 文件越乾淨,注意力越自由。

> **shiftblame = 轉移責任以保持注意力。** 注意力是有限資源;框架的每個機制都在把責任轉移到別處,讓當下的注意力保持乾淨聚焦。

```
老闆 ──揭露意圖──▶ 秘書(預設角色:翻譯需求/建 slug/派發/checkpoint/收尾)
                       │ 開 <slug> 觸發三軌
                       ▼
             迭代(讀 G1/G2/G3 + codebase → 改寫快照,到穩定)
                       │ 穩定(重讀結論不再變)
                       ▼
                  G3 計畫 ──▶ 開發(causal) ──▶ 證據
                       ▲                                    │
                       └──── AUDITOR 驗收不過 → 回 G1 ──────┘
老闆 ──PASS──▶ 收尾歸檔
```

## 0. 命題:轉移責任以保持注意力

注意力是有限資源(context、聚焦、工作記憶)。框架每個機制都是把責任轉移到別處,讓當下的注意力保持乾淨聚焦:

| 機制 | 轉移責任到 | 保持的注意力 |
|------|-----------|--------------|
| 三軌分工(研究者↔開發者↔審查者) | 主對話內的不同角色(切換,非不同 agent) | 各自只注意自己的 scope |
| 秘書(預設角色) | 老闆意圖的翻譯與派發 | 老闆只需揭露,無須親自推進 |
| 子代理外包 | 獨立的唯讀勞務成果 | 主對話不親做讀的負荷,責任仍回主對話 |
| 文件快照(G1/G2/G3) | artifact | 狀態落盤,釋放工作記憶;要時再 re-attend |
| `<slug>` / `<nnn>` | 兩個注意力弧 | `<slug>` 釘住跨迭代穩定的目標;`<nnn>` 承載當輪結論 |
| 兩 checkpoint | 老闆在對的弧上拍板 | 其餘轉移給自由迭代 |

### 兩層模型(機制的核心形狀)

| 層 | 角色 | 形狀 |
|----|------|------|
| **文件層** | 責任落點(blame sink):承載「現在的結論」 | 乾淨、線性、單一職責、結果式快照 |
| **協定層** | 注意力運算:agent 如何讀寫文件 | 多視角注意力、迭代、emergent 收斂 |

注意力是 agent 對文件的**讀法**,不是文件的形狀。乾淨的線性文件正是 transformer 讀得最好的輸入——讓文件乾淨,與讓 agent 用注意力,是同一件事。

## 1. 詞彙(RFC 2119)

MUST(必須)|SHOULD(應)|MAY(得)|MUST NOT(必須不)|SHOULD NOT(應不)。

## 2. 角色

老闆是主角(principal);**秘書是 skill 載入即生效的預設角色**(老闆的幕僚);**三軌角色於開 `<slug>` 時觸發**。三軌是主對話內的角色切換,非子代理實體。

```
             老闆(意圖/PASS)
                   │ 揭露意圖
                   ▼
           秘書 SECRETARY(預設角色)
     翻譯需求 / 建 <slug> / 派發 / checkpoint / 收尾
                   │ 開 <slug> 觸發
       ┌───────────┼───────────┐
       ▼           ▼           ▼   (主對話內角色切換)
   研究者       開發者       審查者
  RESEARCHER  DEVELOPER     AUDITOR
   研究         開發         審查
```

| 角色 | 定位 | 邊界 |
|------|------|------|
| **老闆** | 需求/優先序/風險/PASS | 握兩個真 checkpoint:揭露意圖、PASS |
| **秘書**(預設) | 老闆的幕僚。核心=**翻譯需求**(老闆意圖→可驗證問題)→ **分流判定**(開 `<slug>` 或直接實行)、派發三軌、checkpoint 管理、收尾 | 非決策者(決策歸老闆)。開 slug 時不開發/不審查/不親研究(交三軌或外包);低複雜度任務釐清後直接實行(見 §7) |
| **研究者 RESEARCHER**(研究軌,開 slug 觸發) | 相鄰 G1、G2。視角=需求/Why/邊界/可行性 | 見 SBM-RESEARCHER |
| **開發者 DEVELOPER**(開發軌) | 相鄰 G2、G3。視角=技術/How/開發。寫檔/測試/操作在此,主對話親為 | 見 SBM-DEVELOPER |
| **審查者 AUDITOR**(審查軌) | 相鄰 G3、G1。視角=完成標準/證據/e2e。驗收不過→回 G1 | 見 SBM-AUDITOR |

### 子代理 = 外包唯讀

子代理**永遠唯讀、不承擔任何責任**,僅承接主對話角色(秘書/研究者/審查者)派發的**研究/審查等獨立唯讀任務**。寫檔/測試/操作/commit **只在主對話**。

- **產出非權威**:子代理產出 = 證據/意見**輸入**,非決策。主對話角色 MUST 複核採納並**承擔責任**,不得照單全收(否則等於把責任外包)。
- **獨立性來源**:獨立性來自外包勞務提供的**獨立成果**(一份獨立於主對話的研究結論/審查意見);而此獨立性之所以有效,繫於**責任最終回歸主對話**。子代理是獨立成果的提供者,非獨立責任的承擔者。

## 3. 三文件(角色間妥協的產物)

G1/G2/G3 **各有自己主責**(需求/技術/計畫)。文件不是任一角色的映射——**每份文件是兩個角色在邊上雙向溝通、妥協的產物**。**角色是頂點,文件是邊**:每條邊連接兩個角色,其溝通產出一份文件。

```
                 RESEARCHER
                ╱          ╲
          G1 ╱   (需求)      ╲ G2 (技術)
            ╱                  ╲
      AUDITOR ──── G3 ────── DEVELOPER
                   (計畫)
```

| 文件 | 職責 | 產出 |
|------|------|------|
| G1 需求研究 | What/Why/邊界/可行性/品質定義/變更清單 | `<task>` 候選 |
| G2 技術分析 | How/選型/測試骨架/證據/完成標準 | `<complete>` |
| G3 開發計畫 | 行動序列+驗收 | `<plan>` |

**TDD 回饋**:G3(DEVELOPER↔AUDITOR)驗收不過 → AUDITOR 沿 G1 邊(RESEARCHER↔AUDITOR)回需求重新研究(需求根因,非盲目改開發)。Red → 回 G1 → 重走 → Green,循環至正確實現功能。

## 4. 文件層六不變量(同時保證乾淨 + 不鎖迭代)

1. **單一職責**:一份文件只承擔一個角色;內容與流程狀態不分混。
2. **只寫結果,不寫過程**:文件是「現在是什麼」。第幾輪、誰質疑誰、收斂記錄一律不入文件。過去事實以 git 歷史為權威。
3. **冪等可重寫**:任何時刻能從 codebase + 老闆意圖重生成而不丟資訊。文件不當唯一記憶體。
4. **狀態與內容分離**:流程狀態用極簡欄位承載,不滲進內容結構。改內容不破壞狀態語義,推進不卡住內容迭代。
5. **注意力在讀不在寫**:文件結構絕不表達「誰注意誰」。引用只是引用,不是注意力網。
6. **資料型內容表格化**:清單、屬性、可比較的資料型內容 MUST 以表格呈現;敘述型原則、語義說明、引用保留散文。服務掃讀(乾淨),不適用時不硬轉(不鎖)。適用所有 shiftblame 管理文件(範本、`.shiftblame/`、repo 內 `docs/`)。

## 5. 協定層:注意力迭代(不鎖迭代的引擎)

- **讀 = self-attention**:每輪把 G1/G2/G3+codebase+SOP 當 token 集合,可同時掛多視角(需求一致性/技術可行性/風險/成本/合規)。視角是讀的姿態,不是額外文件。三軌角色即三個制度化視角(研究/開發/審查)。
- **寫 = 落盤當下結論**:把該改的那份覆寫成新快照。增量,不改形狀。
- **收斂 = emergent**:重讀後結論不再變 = 穩定,即終止條件。由「結論還在變嗎」決定,不由「走完幾個閘門」決定。

## 6. 紀律:不變量 + 兩 checkpoint,不靠狀態機

- **文件不變量**(每份文件隨時 MUST 滿足):證據優先、寫當下事實、可查核引用。隨時可審,不綁順序。
- **真 checkpoint 只有兩個**:老闆**揭露意圖**(進入迭代)、老闆 **PASS**(結束)。中間全是自由迭代。
- **三軌互斥(主對話角色切換)**:研究/開發/審查分屬 RESEARCHER/DEVELOPER/AUDITOR,主對話內角色切換。獨立性來自審查(及研究)外包勞務提供的**獨立成果**,因**責任回歸主對話**而有效——子代理是獨立成果提供者,非獨立責任承擔者(見 §2 子代理)。
- **可查核引用**:每條事實陳述 MUST 附 `<檔案路徑>:<行號>`;引用對象變更時同步查核,失效引用等同錯誤。
- **文件先於 repo 改動**:涉及 repo 的改動 MUST 先由 slug 文件承載(G3 `<plan>` 指明該變更);MUST NOT 先改碼再回頭補文件。迭代發生在文件層(讀 G1/G2/G3、改寫快照),repo 改動是穩定計畫後的開發——順序不可倒置。
- **多人協作既有文件保護**:多人協作下,repo 內既有文件(如 `docs/`)預設 MUST NOT 改動,除非老闆明確指定該檔需維護。單人則不受此限(見 §8 分支政策判別)。

證據查證觸發:不確定、新版本/依賴/API、法規/安全/效能/成本、無先例、與老闆直覺衝突——MUST 查證。

## 7. 觸發

- `/shiftblame <text>`:揭露意圖 → 秘書承接釐清 → **分流**(見下)→ 依判定走 slug 或直接實行。
- `/shiftblame`:列未歸檔 `<slug>`。

### 秘書分流(是否開 `<slug>`)

不是所有需求都值得開 slug。秘書釐清老闆意圖後判定,**不為流程完整度讓所有任務進 slug**:

| 判定 | 條件 | 走法 |
|------|------|------|
| 開 `<slug>` | 開發需求:多輪研究、跨檔變更、具完成標準與獨立驗收 | 觸發三軌迭代 → G1/G2/G3 → 開發 → PASS |
| 直接實行 | 低複雜度/配置:設定調整、開關切換、無獨立驗收 | 秘書在主對話釐清後直接做,不建 `.shiftblame/` |

判定問句:「這需要研究→開發→審查的因果鏈,還是只是把設定值改掉?」——前者開 slug,後者直接做。

- **框架自身的演化不走 slug 流程**(避免 bootstrap 循環:框架尚未定穩,卻以框架流程改框架,自我指涉)。直接於主對話釐清 → 改檔 → 自洽檢查。

## 8. 提交規範

- 訊息 `<type>: <繁中描述>`,單行可掃過;繁中描述 SHOULD 約 10~50 字,MUST NOT 多行或多事項冗餘(防膨脹;字數為指引非硬限,MUST NOT 為算字數耗 token)。
- 分支依外部證據:SOP 記載多人協作、或具非本人 owner 的 upstream remote 等 → 走 `feat/<slug>`,秘書收尾 merge;單人本地無上述證據 → MAY 直接 main。

## 9. 框架檔

```
skills/shiftblame/
├── SKILL.md      # 主規範(本檔)+ 預設角色(秘書)= SBM-SKILL
├── GATE.md       # checkpoint、<nnn>、收尾、複審 = SBM-GATE
├── ROLE/
│   ├── RESEARCHER.md  = SBM-RESEARCHER   # 研究軌(相鄰 G1、G2)
│   ├── DEVELOPER.md   = SBM-DEVELOPER    # 開發軌(相鄰 G2、G3)
│   └── AUDITOR.md     = SBM-AUDITOR      # 審查軌(相鄰 G3、G1)
└── TEMPLATES/    # 範本 = 合法文件白名單
    ├── SOP.md       = SBM-SOP
    ├── ROADMAP.md   = SBM-ROADMAP
    └── slug/        # 鏡射 .shiftblame/<slug>/
        ├── SLUG.md  = SBM-SLUG
        └── nnn/
            ├── G1.md = SBM-G1
            ├── G2.md = SBM-G2
            └── G3.md = SBM-G3
```

## 10. 專案工作區 `.shiftblame/`

每個採用 shiftblame 的專案自成本目錄,MUST 經 `.gitignore` 排除於 repo 外。

```
.shiftblame/
├── SOP.md         # 專案執行準則(長期租約,當下事實)
├── ROADMAP.md     # 待開發業務需求(老闆提,現無法實作)
├── <slug>/        # 鏡射 TEMPLATES/slug/
├── tmp/           # 非持久產出(探索性研究/草稿)
└── archive/       # 已歸檔任務(過去事實由 git 歷史承擔權威)
```
