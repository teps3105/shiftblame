# shiftblame — AI Agents 協作框架

正反回饋迴圈框架。會話由老闆自由管理。

1. **回饋即意圖**：老闆回饋為意圖確認素材，不可直接執行，禁止寫入記憶
2. **SOP 紀律**：可更新 SOP 作為全局標準，建立與修改皆需意圖揭露
3. **PRD/PID 筆記本**：老闆的筆記本，agent 可參考與協助整理，不進 slug 鏈
4. **先提出再質疑**：正方提出→反方質疑，四出口（計畫/開發/驗收/展望）各正→反→收斂三輪辯論
5. **迭代收斂**：閘門 FAIL 以收斂產出為起始基線重跑（增量更新不重建）
6. **Shift Blame**：責任跟著老闆走。G1/G2 現在的老闆確認，G3/G4 未來的老闆確認，Agent 為執行工具

## 啟動序列

每次觸發**僅載入索引層**，禁止一次讀入整個專案。依序：
1. **未歸檔偵測**：掃描 `.shiftblame/` 下未歸檔 SLUG.md
2. **四文件載入**：REPO.md → ROADMAP.md → SOP.md → GRAPH.md
3. **Repo 狀態**：git log、status、branch
4. **租約載入檢查**：確認 SOP.md（長期）已載入；確認 SLUG.md 第 8 節（中期）租約欄位；本次載入即短期租約生效。若長期租約未載入，回入口閘門 FAIL
其餘依需求按需載入。

## 觸發

| 觸發方式 | 行為 |
|---------|------|
| `/shiftblame <任意文字>` | 意圖線索 → 啟動序列 → 呈現意圖 → 確認 → 分流 |
| `/shiftblame`（有未歸檔） | 啟動序列 → 呈現清單 → 老闆選擇 → 分流 |
| `/shiftblame`（無未歸檔） | 啟動序列 → 提議 slug → 確認 |
| slug 確認後 | 管理者掃描環境 → 提出子代理策略 → 啟動計畫行為 |
| 驗收 PASS 後 FAIL | 自動觸發 → 同 slug 開新 NNN |

意圖揭露詳 GATE.md。觸發後不直接執行；呈現意圖時**必須包含執行模式**（slug 流程 vs main 直接執行），由老闆決定。

## 模式

四出口迴圈：**計畫（G1）**→ **開發（G2）**→ **驗收（G3）**→ **展望（G4）**。每閘門至少正→反→收斂一輪。老闆不通過以收斂產出為基線重跑。計畫/驗收正方為多子代理盲獨立；開發正方由管理者視情況決定子代理策略。反方皆為質疑者。展望行為為 G3 PASS 後強制觸發，不需觸發表記載。

**G1 入口路徑區分**：詳 ROLE/G1.md。

## 閘門

閘門：G1 → G2 → G3 → G4。每出口收斂完成後，必須對應老闆確認通過才進入下出口。展望行為為 G3 PASS 後自動進入（強制觸發）。正→反→收斂自動推進不需閘門。詳 GATE.md。
分支：同 slug 使用 `feat/<slug>` 分支，agent 禁止直接操作 main。

## 角色與定義檔

四出口×正反。詳 ROLE/G1~G4.md；閘門/收尾→GATE.md；管理者→MANAGE.md；模板→TEMPLATES/；工具→TOOLS/
