# Shiftblame

把已授權的需求完成，以可核對的結果交付。使用者決定目標與授權，專案決定適用規範，代理依證據安排工作。個人語言、稱謂、模型、平台及自動化政策由外部環境管理。

## 理解需求與授權

先從完整對話、repo 與現況理解目標、範圍、限制及驗收。明確行動要求直接承接，既有授權跨回合有效。進度詢問與補充資訊沿用原任務，除非使用者明確更換目標。

先查可查證的事實，再處理技術選擇。只詢問會改變結果或授權的必要缺口；需求已明確時直接工作。需要保留對齊結果時，可使用 [INTERVIEW](assets/INTERVIEW.md)。新對話、恢復與交付本身不構成重新提問的理由。

產品範圍、不可逆影響或正式發布超出既有授權時，說明差異並取得適用授權。等待時完成不依賴答案的工作。一般技術選型、修復與驗證由代理依證據處理。意圖理解見 [think](../think/SKILL.md)。

## 規劃與實作

需求寫成可觀察結果，包含情境、操作、預期結果與失敗邊界。重構或遷移可要求外部行為保持，另列真正要改善的條件。明確區分現況與目標。

把工作拆成能走通實際入口的片段。先確認驗收入口，再依依賴實作；需要同步維持一致的跨檔修改一起處理。大型遷移可先提供相容形式，逐批更新消費者後移除舊入口。原型用來回答具體未知，原型成功不代表產品已驗收。

依任務選擇適用方法：

- 修補可重現錯誤時，TDD 可用失敗測試確認原因，再驗證修復。
- 定義新行為時，BDD 可把正常與邊界情境寫成可驗證場景。
- 調整介面或跨模組責任時，SDD 可先定契約、型別與資料結構。

方法以風險與證據為準。測試依真實回歸風險選擇，不以檔名同批或固定方法代替驗收。模組邊界見 [STRUCTURE](references/STRUCTURE.md)，難定位問題見 [DEBUG](references/DEBUG.md)。

## 協作與版本管理

修改前核對 repo、分支、工作樹與既有差異。保護使用者及無關工作，提交只包含本次範圍。分支、提交格式與整併策略遵守專案規範；有授權才發布或改寫共享歷史。

平台與授權允許分工時，主代理維持需求與整合責任。委派須有明確範圍、交付與驗證入口，避免多人同時改同一份檔案。審查者對受審來源唯讀。主代理核對局部成果，整合後驗收完整行為。

有進展才重試。相同問題持續時重新檢查假設、來源與方法。真正缺少資訊、授權或環境時揭露阻塞，繼續可獨立完成的工作。持續完成整體已授權任務，進度更新說明有意義的結果與下一步。

## 驗證與交付

選擇能支持需求判定的最小足夠證據。CLI 檢查正式命令、退出碼與輸出；格式是契約時核對檔案；視覺與外部應用依需要操作或渲染。盡量驗證自有模組的真實組合，只替代必要的外部邊界。

預期結果從需求或獨立案例取得，避免複製實作公式。測試通過只證明其覆蓋範圍。逐項記錄滿足、未滿足或未驗，以及操作、輸入與結果。修改後重驗受影響證據，完成必要回歸及整合檢查。

審查依風險與證據缺口取用 [AUDIT](references/AUDIT.md)。交付說明實際完成、驗證結果、殘餘與未驗項。需要使用者裁決的產品取捨才請其確認，不以固定收尾程序代替完成判定。

## 文件與交接

文件隨行為更新，依 repo 慣例安排位置、命名、結構及維護方式。事實保有明確權威來源，避免描述互相矛盾。撰寫方法見 [DOCS](assets/DOCS.md)，重整時可用 [rewrite](../rewrite/SKILL.md) 保存原稿。

工作暫存放 `.shiftblame/tmp/`。[AGENTS](assets/AGENTS.md) 與 [ROADMAP](assets/ROADMAP.md) 是可選範本。一般將兩份文件放 repo 根。若上游已追蹤任一同名文件，或有多位 Git 作者，則放 `.shiftblame/`，保護既有 tracked 文件。框架以 Git local exclude 忽略本機資料，不新增 `.gitignore` 規則。

使用 `sb workspace migrate` 搬移現有本機內容；`init` 才補缺少範本，`check` 唯讀核對，`clean` 顯式清理既有忽略污染。細節見 [MECHANISMS](references/MECHANISMS.md)。

跨回合或換代理時依 [save](../save/SKILL.md) 保存交接，再由 [load](../load/SKILL.md) 核對接續。交接不新增授權，也不恢復產品檔案。撤除失敗成果見 [dice](../dice/SKILL.md)。

CLI、通用防護與外部政策入口見 [MECHANISMS](references/MECHANISMS.md)；交接契約見 [HANDOFF](references/HANDOFF.md)；查證方法來源見 [SOURCES](references/SOURCES.md)。
