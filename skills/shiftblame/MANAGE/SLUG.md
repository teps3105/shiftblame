# SLUG — SLUG.md 維護規則

建立新 slug 時，管理者協調建立 `.shiftblame/<slug>/SLUG.md`，再由執行者建立第一份 `task.md`。

## 五分類結構

SLUG.md 為結構化流程紀錄，包含五個分類：
1. 本輪目標
2. 管線狀態紀錄
3. 殘餘風險與交接事項
4. BossPreview/退回紀錄
5. 待收尾整理

記錄者為管理者，內容只能追加不得修改或刪除。

## 生命週期

建立時產生 → 開發中持續追加 → 歸檔後作為歷史紀錄保留。

## 與其他檔案的關係

- SLUG.md 不替代 task.md、result.md、red.md 或 blue.md
- 角色正式產物仍寫入各自任務目錄
- 任何還沒完成、還在爭議中、只屬於本輪流程的待辦，不得寫入 ROADMAP
- ROADMAP 只能在歸檔後更新，從 SLUG.md 與實際完成結果整理成穩定產品路線
