# 實作與驗收安排

G3 用 G1 的 AC-ID 安排如何驗收，並依 G2 記錄實作順序、依賴、變更範圍及適用測試。只保留讓工作可執行及可驗收的必要細節。

每個里程碑有可交付價值。功能按完整行為拆成小片段：一個片段走通實際入口到可觀察結果，列出對應 AC、必要前置片段、變更範圍及驗證。先打通最窄路徑，再依前一片段的結果補邊界與失敗情境。獨立工作可以並行，只有真正阻止開工的工作才列為依賴；需要一起保持一致的跨檔變更作為一組完成。

片段是同一授權內的工作分解，不自動成為新里程碑或新核准點。使用現有 test／build 責任段逐步測試、實作與整合；一個片段完成的判準是其行為可展示或驗證，其他片段尚未完成時仍持續整體工作。

全域改名、資料格式替換等無法單獨落地的寬幅重構，先新增相容形式，再依實際影響分批遷移，所有消費者完成後移除舊形式。每批維持必要檢查可通過；確實不能獨立成立的批次明列共同整合與驗證點，沿既有授權選擇隔離方式。

驗收方法依結果選擇：自動測試、實際使用、畫面／渲染、外部系統結果都可成為合適證據。自動化不涵蓋的部分明示方法與限制。G1、G2、G3 以穩定識別與來源回指建立可核對的對應。

計畫有錯就依新證據修正，僅重驗受影響部分；維持原需求的技術修正沿用既有授權。

完成計畫時，下一個可做片段、真正依賴、驗證入口及通過判準都應可辨識；尚待決定的問題回到 G2，不以猜測排成確定待辦。
