# main 具名交接

直接實作需要跨回合、換代理或交給其他工作階段時使用。main 是工作模式，可以位於任一已授權分支；活動 slug 使用 save/resume 的 SLUG 回指方式。

## 保存與發現

```sh
# 先由代理寫好並核對 tmp 內的 Markdown 交接草稿
sb handoff save release-280 .shiftblame/tmp/release-280-notes.md
sb handoff list
sb handoff show release-280
```

`save` 把草稿文字與當下 repo 實體位置、分支、HEAD、索引及工作樹指紋保存到 `.shiftblame/tmp/main/<task>/handoff.json`。task 用明確的工作名，同一工作重存同名，另一工作另取名稱；命令不自動選最新項。原子更新前先核對新內容，失敗保留舊快照；完成後仍以 show 讀回。

草稿依實際需要包含：

- 目標、目前範圍與原授權來源；後來修正仍以使用者最新指示為準。
- 已完成及待完成工作、重要決策與正式來源回指。
- 未提交工作與使用者修改如何區分；快照不包含產品檔案備份。
- 已驗結果、環境與證據位置，未驗項及真正阻塞。
- 下一步的具體操作、預期觀察、必要讀取文件與技能。

Git 指紋排除根目錄下精確命名為 `.shiftblame/` 的觀測及交接變化；涵蓋受版本控制的變更與未忽略的未追蹤內容。大小寫不同的索引路徑及巢狀同名目錄仍核對。被忽略的外部資料、服務狀態與環境相容性仍需在文字及來源中說明，不能由指紋推定。

## 恢復與差異

`list` 用於查找工作，`show <task>` 用於讀取指定快照、完整性檢查與現況比較。show 不切分支、不還原檔案、不更新授權，也不把快照標記為已消耗。

分支、HEAD 或工作樹有差異時，代理核對實際 diff、正式文件與對話，判斷已完成工作及證據失效範圍。所有已存在變更先保留；只在真正需要新增授權或選擇不同目標時詢問。指紋相同僅證明其涵蓋輸入未改，不能證明需求已滿足。

目前存在活動 slug 時先接續該流程；舊 main 快照可讀作資料，不取代活動 G1。原檔損壞、缺失、位置不符或 Git 無法查證時，保留原資料，從正式來源重建可核對的落點。

同名已有損壞快照時，CLI 拒絕覆蓋。先把該檔保存到 tmp 的診斷位置並核對副本，再移開該 task 的損壞 `handoff.json`，才能從已查證的現況重新保存；完整性雜湊只能發現內容不一致，不是來源簽章。

## 模式邊界

未初始化及合法直接實作狀態可保存，無須先執行 init。ended 流程須依既有收束條件完成後才保存 main 工作；`sb init --main` 專門收束已結束的 slug，並非一般 main 作業的啟動命令。活動或損壞流程不能靠 handoff save 改成直接模式，查詢仍可用於診斷。

保存不要求乾淨工作樹；它記錄未提交狀態，讓下一個代理核對接續。需要具名 Git 分支及可讀取的輸入；Git 尚無首次提交時 HEAD 可明示為空。任務路徑及保存目錄須在目前 repo 的正式 tmp 位置；拒絕越界與外指目錄。

同一 task 保存中會有 `.save.lock`；另一個保存明確拒絕，讀取仍可使用已完成的舊快照。程序中斷遺留鎖檔時，先確認原程序已結束及該 task 的實體位置，再只清理其殘留鎖並重存，保留舊快照與原稿。

正式快照原子替換成功就是保存完成；若之後暫存或鎖檔清理失敗，命令仍回報成功並附殘留警告。先用 show 核對新快照，再依上述方式處理殘留；替換前失敗則維持舊快照，並保留原始失敗原因。

目前遇到 submodule、未忽略的巢狀 repo 或無法安全表示的檔案路徑會明確拒絕建立指紋。此時保留草稿並說明缺少的查證範圍，不把部分輸入宣稱為完整快照；跨機器／搬移 repo 的交接須核對新位置後重新保存。
