# 以原症狀診斷

用於根因不明、反覆修補無進展、間歇錯誤或效能退步。目標是讓每次變更都有能分辨對錯的回饋；原因已明確的小修正直接使用適當驗證。

1. **建立重現**：記錄使用者的原症狀、輸入與環境，選能走到該路徑的測試、CLI fixture、HTTP／瀏覽器操作、trace replay、最小 harness 或版本差異比較。實際執行並保存失敗證據；「沒有崩潰」通常不能證明症狀已消失。輸出隱去秘密，保留判斷所需訊號。
2. **縮小案例**：逐項移除無關輸入、步驟或依賴，每次確認仍是同一失敗。縮到足以區分原因即可；保留原案例供修復後重驗。間歇問題記錄嘗試數、失敗數及條件，改善重現率；效能問題先固定輸入與量測基準。
3. **區分假設**：仍有競爭解釋時，列出少量候選根因、各自預測及能推翻它的觀測。優先以最低成本區分候選；每次探針或變更對應一個問題。使用斷點、針對性日誌或 profiler，臨時探針加可查找的標記。
4. **修復及重驗**：在能捕捉真實問題模式的介面保存必要回歸案例，確認失敗後修根因，再重跑最小案例、原始情境與受影響回歸。若測試介面不足以重現，記錄缺口及替代證據，不建立只驗鄰近簡單情境的假保障。
5. **收尾**：確認原症狀的實際結果、移除臨時探針、將必要重現資料留 tmp，記錄被證據支持的根因、修復及殘餘限制。

無法重現時，列出已嘗試方法、缺少的環境或資料，繼續獨立的靜態查證及取證準備。只有真正需要使用者提供的資訊或新增操作授權才詢問。靜態推論可支持候選修復，完成狀態仍按實際證據標示；速度與自動化程度依環境選擇，不以形式門檻阻擋可用證據。
