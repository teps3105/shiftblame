# 實作與整合

依已授權結果與技術決策實作，優先重用既有能力。讀取相關呼叫與消費者，修正共同根因，保護無關使用者變更。

以可診斷、可回復的一組改動推進；依影響執行必要檢查。可獨立分工時使用隔離工作區，整合者核對變更與測試。外部應用由其適用技能承接來源保存與實機驗證。

依 [PLAN](PLAN.md) 逐個完成有可觀察結果的片段，採測試先行時依 [TEST](TEST.md) 取得失敗到通過的回饋。原症狀未消失、根因不明或連續修補無進展時，依 [DEBUG](DEBUG.md) 改用可反駁假設及定向取證。每個片段的結果用來調整後續做法，直到整體已授權工作完成。

發現計畫或技術前提錯誤時回對應責任段修正並續行；只有需求／授權改變才重走 intent。與實作同批更新受影響文件，保持描述一致。

完成功能或一致的修正批後，精準 staged，經 sb commitmsg 提交。進入 verify 前保持受驗工作樹乾淨；驗收中需修來源時先回實作，再重驗受影響範圍。
