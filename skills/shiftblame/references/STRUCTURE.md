# 結構與驗證方法

跨模組、介面、語言或系統變更時，先釐清責任、依賴與狀態權威，再選擇驗證。以下提供分析方法；架構限制、檢查強度與例外程序依專案契約及任務風險決定。

## 找到責任與來源

以當前程式碼、目錄及建置設定判斷實際責任。新增內容先找既有擁有者；有獨立責任與公開契約時再考慮新模組。生成物、第三方內容及資源保留必要來源。

依賴分析可結合程式、資源與生成內容。逐邊核對實際呼叫及公開入口，未知依賴另列。循環是否違反架構由專案規範判定，不把所有系統預設為 DAG。事件、反射、callback 與注入仍依實際責任及契約分析。

## 評估介面

找出呼叫者必須理解的規則、重複協調及散落修改。比較移除或增加某層後，複雜度是否減少，還是轉移到更多消費者。

高成本或難逆轉的決策，依需要比較可行方案。使用相同情境檢查入口、資料、順序、不變量、錯誤及依賴，說明取捨與驗證方式。外部依賴按實際需要注入或替代，避免為假想變化增設介面。

釐清狀態由誰修改、誰能觀察，以及快取、預測或同步副本如何校正。跨模組用例的組裝責任應能由來源與契約辨識。

## 安排變更

1. 判斷是內部修改、公開介面變更、責任調整、換語言或系統替換。
2. 從實際依賴找受影響消費者，記錄證據不足的範圍。
3. 定義外部行為與契約如何保持或改變，選出能驗收的檢查。
4. 實作後檢查真實組合，確認消費者、生命週期與錯誤處理。
5. 整併、依賴或生成輸入改變後，重判證據失效範圍並重驗。

保護既有變更。驗證會改寫來源或副作用不明時，使用隔離工作區。檢查結果綁定實際交付輸入，不以舊結果推定新內容已通過。

## 依風險取證

| 變更 | 可用證據 |
| --- | --- |
| 責任或依賴 | 當次來源掃描、公開入口、實際依賴圖與適用架構規則。 |
| 動態入口 | 目標範圍、契約及定向執行；軌跡只證明已走過路徑。 |
| 介面與組裝 | 使用必要依賴的契約、整合與失敗場景。 |
| 換語言或替換系統 | 型別與資料相容性、生命週期、舊資料升級及切換行為。 |
| 正式產物 | 已知輸入、工具鏈、包內內容及目標平台的實際流程。 |

大型遷移可分批保持相容，驗證各批後再撤除舊入口。有持久化狀態時，另核對中途失敗、舊回呼及資料回復方式。

## 記錄結果

區分已驗、違規、未驗及已接受例外。例外記錄具體範圍、理由與移除條件，適用授權依專案規範核對。未知或未執行項不宣稱通過。

紀錄依變更規模縮放，可包含目的、責任模組、消費者、契約差異、必要檢查、實際結果，以及被停止條件擋住的未驗項與卡點。架構選擇回指專案來源；一般授權與驗收原則見 [主技能](../SKILL.md)。
