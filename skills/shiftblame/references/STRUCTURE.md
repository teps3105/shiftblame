# 結構與驗證紀律（通用技術作業規程）

用途：長期新增功能、修正、重構、換語言與替換系統時，限制未宣告的結構偏移；供 plan／build／verify 段的技術義務取用。合格的架構演進可以改變邊界，但必須留下理由、影響與驗證；不以目錄永不變動為目標。本文是技術作業程序——意圖路由、階段、授權、提交與 PASS 由本框架（SKILL 主文）承載，本文不另設角色或放行權。「必要檢查通過」只表示指定證據成立，不等於產品 PASS。

未接入結構檢查的既有專案：先用已知責任與現有工具守住本次變更，揭露尚無全圖／CI 證據；維持已知邊界、不新增已知偏移並揭露未驗範圍——安裝框架不等於授權舊專案全面接入。

## 1. 固定規則

| ID | 規則 | 必須留下的證據 |
|---|---|---|
| R1 | 自有檔案有唯一邏輯歸屬；生成物與第三方內容有明確範圍及來源 | 歸屬可從目錄與歸位對照核對；來源有對應 |
| R2 | 模組只使用其他模組明確公開的入口 | 實際依賴以當次掃描對照；未知邊另外列出 |
| R3 | 每種狀態的修改與每個跨模組用例有明確責任方 | 寫入契約、跨模組行為驗證 |
| R4 | 換語言不默認改模組責任；介面只有一個權威定義 | 模組識別、工具鏈及契約回指 |
| R5 | 必要檢查沒有證據就不是通過；例外可追蹤且有界 | 檢查結果與例外紀錄 |
| R6 | 不以修改規則或重錄基線掩蓋新增偏移 | 舊→新邊界差異 |
| R7 | 素材與編譯產物可追溯至來源，正式包從已知輸入建立 | 重製紀錄、工具鏈身分與包內驗證 |

模組間合併各語言與資源證據後的靜態依賴圖必須無循環（DAG）——逐邊合法不夠，分語言無環也不能替代合圖無環；callback、注入介面與訊息互動按其契約判斷，不用全域事件或反射藏起真正的業務依賴。

## 2. 佈局與事實來源

- 模組清單、責任與依賴以目錄結構與程式碼為**事實來源**——不建立第二份宣告檔，不為「宣告與現實同步」做任何工作；判斷依賴以當次掃描為準，不憑記憶或提交訊息。
- 新增內容先決定責任歸屬再落位；具體骨架由專案工具鏈或領域技能定義，框架只要求：唯一歸屬、生成物與第三方有明確範圍、**不使用 shared／common／utils 等無責任收容區**。
- 既有專案未遷移時記錄現有路徑映射、遵守其既定布局並標記 legacy；經授權遷移時再收斂。

## 3. 歸屬與依賴裁定

依下列順序決定新增內容的位置：

1. 找到決定該內容如何變更的既有責任模組，優先留在該模組。
2. 僅因增加使用者，不搬移所有權。
3. 新內容有獨立責任與對外契約時，才新增具名模組；不按檔數或語言拆模組。
4. 專屬組裝與內容可由該專屬模組擁有；實際跨範圍使用時才評估抽出。
5. 通用能力也有具名責任（如 ui_kit）；無責任收容區不存在。

跨模組用例必須有擁有者；裝配模組（app 層）是受檢查的組裝點，不是所有業務規則的例外區。狀態權威是「誰負責某狀態轉換」——唯讀快取、預測狀態及同步副本須說明回寫／校正契約。

## 4. 每次變更的作業程序

- **A 確認範圍與影響**：判斷變更屬內部修改、公開入口變更、新責任、換語言或系統替換（可多類）；由實際變更與依賴找消費者，不憑提交者自述。依賴證據不完整時擴大驗證範圍並明列。普通內部修改不需要另寫架構提案。
- **B 定義必要的契約變更與驗證**：不改邊界用既有契約並選出保護本次行為的檢查；改邊界記錄舊→新、理由、消費者與驗證。縮小掃描、降低檢查必要度都視為檢查能力變更。
- **C 實作與保存**：跨模組只使用公開入口；動態／反射入口補上目標範圍與契約標註；素材後製回到來源或可重製步驟；不為修綠測試而拓寬邊界。
- **D 執行必要檢查**：結果綁定實際交付輸入（或涵蓋全部相關輸入的快照識別）；合併、rebase、依賴或生成輸入變動後重判失效範圍並重驗，可重用未受影響證據但須有依據。驗證階段保持受驗 repo 唯讀；需要寫入的匯入、編譯與匯出在已識別的隔離副本進行。
- **E 複核與回指**：證據回指原需求與本次變更；先前有效不等於目前有效。

## 5. 檢查能力與觸發矩陣

| 檢查 | 必要觸發 | 證據與限制 |
|---|---|---|
| 歸屬與依賴掃描 | 每次候選變更 | 目錄結構＋當次掃描的合併依賴圖；未知不可被忽略 |
| 合併依賴圖循環 | 邊界或依賴變動時 | 程式／資源／生成內容的合併圖；分語言無環不能替代合圖無環，圖不完整則 unverified |
| 各語言程式邊界 | 該語言來源或公開入口改動 | 編譯器／分析器的符號與實際引用；只有套件名不足 |
| 動態入口 | 入口、允許目標或相關消費者改動 | 明列契約＋定向測試；執行軌跡不是完整性證明 |
| 契約與組裝 | 行為、契約或消費者改動 | 提供必要依賴的測試場景 |
| 正式包與使用者流程 | 發布前；及匯出、工具鏈、橋接等變更 | 隔離建置、包內清單及實際流程；按目標平台執行 |

尚無適配器的語言以人工證據限期例外處理，不能以未知副檔名得到空白依賴圖後報成功；跳過、逾時、崩潰、沒有輸出一律不是通過。

## 6. 結果、例外與既有偏移

| 結果 | 處置 |
|---|---|
| checked | 指定範圍已驗證符合；只對該範圍成立 |
| violation | 必要條件不符，阻擋；修正後重驗 |
| unverified | 沒有足夠證據，必要項預設阻擋 |
| accepted_exception | 明確接受特定缺口；保持例外身分（宣稱 checked 即違規） |

例外須具體、有界：記錄對象、原因與移除條件，經既有授權；超出範圍或到期即失效——agent 不能因需要過檢查而自行接受新的風險範圍。既有偏移基線是債務清單（記於專案工作紀錄），不是正確性證明；只吸收已確認的舊項；新增違規排除於吸收範圍，已清除項目由基線除名。例外延長、重新基線化與檢查降級須列出差異並經適用審閱。

## 7. 四種長期演進的額外步驟

- **新增大型功能**：先指定責任與跨模組用例擁有者，再新增公開入口；持續擴大某舊模組責任時，即使沒有跨目錄引用也要重審責任。
- **抽取共用能力**：先決定誰維護行為、列出原消費者；抽取後驗證既有行為與生命週期，不能只測新模組；移除舊實作或保留有到期條件的相容入口，避免兩份權威。
- **加入／替換語言**：保持模組識別及對外語義；驗證消費者、生命週期、錯誤與目標平台——編譯成功不能替代邊界或使用者流程驗證。
- **替換舊系統**：列出權威的適用資料範圍、切換時點、舊寫入拒絕方法與退場條件；有持久化資料時驗證舊資料升級、中途失敗與舊回呼晚到；切換後確認舊路徑不再是第二個寫入者。

## 8. 驗證依變更實際影響選擇

- 行為改動 → 跑真實流程與日誌；視覺改動 → 取得新鮮畫面目視核對；語言邊界與正式產出 → 另驗證相應工具鏈及產物。
- 證據綁定實際交付輸入；修改後重判失效範圍。空輸出、綠色資料測試或檔案存在都不構成完成——與假測試判準（TEST）同向。
- 未跑檢查標 unverified，不以工具缺席假裝完成；有效例外須具體、有界並依既有授權處理。

## 9. 最小變更紀錄

放既有工作紀錄（tmp）即可，不另建第二套狀態帳本；隨變更規模縮放，無邊界變更不填虛構提案：

```text
變更目的：
責任模組及消費者：
邊界／狀態權威差異：無，或舊→新及理由
必要檢查：命令／範圍／實際結果／證據位置
未滿足條件及下一步：
```

## 10. 與八段的銜接

| 段 | 本文提供的技術內容 |
|---|---|
| intent／requirement | 偏移目標、範圍、責任與使用者可觀察結果 |
| research／plan | 真實依賴、語言能力、契約差異與必要驗證（§4 A-B） |
| test／build | 契約測試與符合契約的實作（§4 C） |
| verify | 唯讀複核輸入與證據、實際行為、四態結果與例外（§4 D-E、§5-6） |
| done | 回指結果及仍有效的債務／例外；不由本文宣布 PASS |
