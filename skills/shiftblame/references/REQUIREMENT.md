# 需求與契約

G1 記錄使用者、情境、操作、可觀察結果、失敗邊界及範圍。先確認與本次需求相關的現況；依相關性回讀既有決策。

概念有歧義時，以具體正常／邊界情境和現有實作對照；使用者期望與目前行為不同時，明示哪個是現況、哪個是目標。必要澄清依 [think](../../think/SKILL.md) 的前提順序處理。專案術語按 [DOCS](../assets/DOCS.md) 保存唯一有效定義。

每項可驗收需求有穩定 AC-ID。可用單行鍵值或 Given／When／Then 分段格式；現狀描述基準，消融說明其價值。行為保持是有效需求：重構、遷移或修補可以要求結果不變，同時明定真正要改善的條件。維護、可靠性及開發者情境均依可觀察結果描述，格式用於追溯需求。
