## 三面向範本

以下各段分別複製至 G1.md、G2.md、G3.md。每份只有一個 `## 回指記錄`；定義與證據分區。G1 於時點 1（research→plan）、G2 於時點 2（quality→build）封存；封存後定義改義須回 requirement 重新核准。

時點通過是暫時性的：時點封存的是「當下成立的標準與依據」，不是永久豁免。下游段連續失敗時，受影響的上游時點會被標記待重審（hook 段注入顯示「時點待重審」）；回退修正後讓該時點的邊再次推進，即重審通過、標記解除。失敗反覆出現時先判斷根因在哪一層——計畫依據不成立回研究、品質安排不成立回計畫、實作偏離回品質——不在當前段硬撐。

slug 的文件結構是三區循環模型：每區兩個責任段對應一份 G 檔，區與區之間以時點關卡銜接（時點 1／2 獨立審查，時點 3 加使用者終審）；通過後由後區對前區建立回指，三區形成閉環。

```
                      一區 G1：探索與驗證
                     （定義需求 → 技術驗證）
                      requirement → research
                     ▲                    ＼
           C 通過＝時點 3                     ＼ A 通過＝時點 1
       （三區→一區，閉環；--new-ms 開下一里程碑）＼
           ＼                                  ▼
一區回指三區                                      二區 G2：方案設計與品質
    ＼                                          （方案規劃 → 品質策略）
三區 G3：開發實作與驗收  ◀── B 通過＝時點 2 ──     plan → quality
（開發實作 → 測試驗收）
build → verify

回指（通過後由後區指向前區，與前進方向相反，構成 G1→G3→G2→G1 三角循環）：
  二區回指一區：G2 ─▶ G1（時點 1 審查完成後，G2 回指已封存的 G1 定義區 hash）
  三區回指二區：G3 ─▶ G2（時點 2 審查完成後，G3 建立時回指已封存的 G2 定義區 hash）
  一區回指三區：G1 ─▶ G3（時點 3 審查完成後，G1 回指區記「回指 G3」——受驗提交與驗收閉環）
```
