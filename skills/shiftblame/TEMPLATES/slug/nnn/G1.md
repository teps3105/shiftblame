# SBM-TM-G1 — 外部研究規劃視角

## 1. 範圍

G1 為外部研究規劃視角的正反收斂軌，與 G2 內部技術實作視角分軌進行。正方由主 session 擔任（身份切換），反方由子代理獨立對抗。側重將老闆意圖翻譯為可執行計畫、界定外部研究範圍與證據需求。正反收斂完成後，實作交執行者承接。規範詞彙依 SBM-SKILL §3.1。讀寫中文 MUST 使用 UTF-8。

## 2. 正方：計畫提案

### 2.1 核心職責

創造性工作前 MUST 先探索需求邊界（意圖、約束、設計空間）再規劃。涵蓋：

- 需求定義
- 5W1H 規劃（Why／What／Who／When／Where／How 六維度）
- 可行性評估（需求層次「能不能做」，技術「怎麼做」歸 G2）
- 品質定義（業務驗收標準一句話：每項需求被涵蓋、流程可走通、產出符合老闆業務意圖）
- 變更清單（標的 + 內容 + 動作）
- 殘餘風險
- 證據需求標示

### 2.2 產出格式

| 項目 | 內容 |
|------|------|
| ① 5W1H 計畫摘要 | 每維度一段 |
| ② 變更清單表 | C#／標的／內容／動作 |
| ③ 殘餘風險表 | R#／風險／H-M-L／建議 |
| ④ 可行性結論 | — |
| ⑤ 證據需求清單 | 描述需求；證據來源選擇交 G2 |

### 2.3 邊界

技術來源選擇、官方文件與業界範例充分性判定、技術選型 MUST 交 G2 承擔。計畫為貼合老闆技術直覺而省略證據／反證／替代方案者 MUST 標迎合風險。

## 3. 反方：計畫質疑

從外部視角挑戰正方計畫。質疑方向：

- 大方向是否對齊老闆意圖
- 可行性是否可靠
- 需求衝突
- 完整性（變更清單遺漏／風險低估）
- SOP 合規性
- 業務邏輯
- 正反收斂軌一致性
- 迎合風險
- 證據需求完整性

### 3.1 標註格式

`D[N] [HIGH/MEDIUM/LOW]：質疑摘要`

| 等級 | 定義 |
|------|------|
| HIGH | 方向問題／SOP 衝突／嚴重遺漏 |
| MEDIUM | 完整性不足／風險低估 |
| LOW | 建議改善 |

結論段落 MUST 彙整風險清單 + 建議方向。閘門與決策歸老闆／管理者；反方專司質疑。

## 4. 越權防線（路由出口）

### 4.1 技術決策路由

技術選型／架構／演算法／測試規範屬 G2。G1 遇此類需求 MUST 轉交 G2。

### 4.2 產出路由

反方專司質疑，產出 MUST 回傳管理者。遇寫檔需求 MUST 限於白名單 G1.md+G2.md；額外檔案 MUST 走白名單外路由（記入技術債或歸管理者）。`<nnn>` 無閘門。PASS 歸 slug 層級由老闆。

### 4.3 職權邊界

G2 技術選型質疑與證據來源選擇歸 G2 反方職權。G1 遇此 MUST 轉交 G2。

## 5. 收斂：研究計畫

### 5.1 流程

由管理者執行，綜合正方提案與反方質疑，產出 G1 視角最終計畫：

1. 正方主 session 產出 + 反方子代理質疑整合
2. 風險逐項回應（承認／反駁／部分承認／記入技術債）
3. 意圖校準
4. 計畫修訂
5. 證據需求收斂交 G2 查證

### 5.2 收斂產出

- 風險回應表
- 最終變更清單
- 最終 5W1H
- 最終殘餘風險
- 可行性結論
- 證據需求清單

### 5.3 分軌獨立性

G1 與 G2 正反收斂分軌不分先後。G1 MAY 參考前 `<nnn>` 的 G2 結論校準；當前 `<nnn>` 的 G2 產出作為獨立軌各自收斂。G3 為共識後執行規劃層（非正反收斂軌），承接 G1+G2 基線。

### 5.4 `<task>` 產出

收斂 MUST 產出 `<task>`（任務序列）供執行者執行。`<task>` 序列為離散編號清單（T1/T2/…），每項 MUST 可獨立 commit。
