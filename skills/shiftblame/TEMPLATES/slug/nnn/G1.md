# G1 — 外部研究規劃視角

> 與 G2 分軌進行。正方主 session（身份切換）、反方子代理獨立。

## 1. 正方：計畫提案

創造性工作前 MUST 先探索需求邊界（意圖、約束、設計空間）再規劃。涵蓋：

- 需求定義
- 5W1H 規劃
- 可行性評估（需求層「能不能做」；技術「怎麼做」歸 G2）
- 品質定義（業務驗收一句話）
- 變更清單（標的+內容+動作）
- 殘餘風險
- 證據需求

**產出**：

| 項目 | 內容 |
|------|------|
| 5W1H 摘要 | 每維度一段 |
| 變更清單表 | C#／標的／內容／動作 |
| 殘餘風險表 | R#／風險／H-M-L／建議 |
| 可行性結論 | — |
| 證據需求清單 | 來源選擇歸 G2 |

**邊界**：技術選型、官方文件充分性判定、測試規範 MUST 交 G2。為貼合老闆直覺而省略證據/反證/替代 MUST 標迎合風險。

## 2. 反方：計畫質疑

從外部視角挑戰正方：

- 大方向是否對齊老闆意圖
- 可行性是否可靠
- 需求衝突
- 完整性（變更清單遺漏/風險低估）
- SOP 合規、業務邏輯、正反收斂軌一致性
- 迎合風險、證據需求完整性

**標註**：`D[N] [HIGH/MEDIUM/LOW]：摘`

| 等級 | 定義 |
|------|------|
| HIGH | 方向問題／SOP 衝突／嚴重遺漏 |
| MEDIUM | 完整性不足／風險低估 |
| LOW | 建議改善 |

結論 MUST 彙整風險清單+建議方向。反方專司質疑不做決策。

## 3. 越權防線（路由出口）

- 技術選型/架構/演算法/測試規範歸 G2，遇此 MUST 轉交。
- G2 技術選型質疑與證據來源選擇歸 G2 反方職權。
- 反方產出 MUST 回管理者；寫檔限白名單 G1.md+G2.md。
- 額外檔案記技術債或歸管理者。
- PASS 歸 slug 層級由老闆。

## 4. 收斂：研究計畫

管理者執行：

1. 正方產出+反方質疑整合
2. 風險逐項回應（承認/反駁/部分承認/記技術債）
3. 意圖校準
4. 計畫修訂
5. 證據需求交 G2 查證

**產出**：風險回應表、最終變更清單、最終 5W1H、最終殘餘風險、可行性結論、證據需求清單、`<task>` 序列（T1/T2/…，每項 MUST 可獨立 commit）。

G1/G2 分軌不分先後。G3 承接 G1+G2 基線。
