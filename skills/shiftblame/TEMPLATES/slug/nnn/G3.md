# G3 — 實作計畫

> 承接 G1+G2 穩定結論,cross-attend 產 `<plan>`。本檔只寫當輪最新 `<plan>`,禁跨輪累積敘事;歸檔以 git 歷史為權威。

## 1. `<plan>` 四段結構

`<plan>` = 實作策略 + 行動序列 + 驗收流程 + 變更預案(條件段,無預期風險可省略)。容器:內含 `<task>` 參照 + 明確化 `<complete>` + 實作策略 + 驗收流程。

| 段 | 內容 | 權威 |
|----|------|------|
| ① 實作策略 | 複雜度判定→派發策略 | SBM-GATE §4 |
| ② 行動序列 | `<task>` 執行順序+依賴(causal) | G1 變更清單 |
| ③ 驗收流程 | 明確化 `<complete>` 當輪清單 | SBM-G2 §3 格式 |
| ④ 變更預案 | Minor/Major 預期風險 | SBM-GATE §5 |

G3 的本質是 cross-attention:每個計畫項逐一引用 G1/G2 結論,非重抄研究。

## 2. Minor/Major 變更模型(權威在 SBM-GATE §5)

| 類型 | 範圍 | 動作 |
|------|------|------|
| Minor | 當前 `<nnn>`:順序/驗證/細節調整 | commit `change(<slug>): <摘>` |
| Major | 新 `<nnn>`:目標/完成標準/架構改變 | 退回迭代重新研究 + 新 `<plan>` |

## 3. 邊界

計畫方向/技術選型歸 G1/G2 研究。PASS/FAIL 歸 `<slug>` 層級由老闆。
