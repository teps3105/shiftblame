# G3 — 共識後執行規劃層

> 承接 G1+G2 收斂基線產 `<plan>`。**非正反收斂軌**（正反收斂限 G1+G2）。反方合理性未經業界先例充分證成；殘留風險由 SBM-GATE §6 觸發點② 獨立審核承擔。

## 1. `<plan>` 四段結構

`<plan>` = 實作策略 + 行動序列 + 驗收流程 + 變更預案（條件段，無預期風險可省略）。容器：內含 `<task>` 參照 + 明確化 `<complete>` + 實作策略 + 驗收流程。

| 段 | 內容 | 權威 |
|----|------|------|
| ① 實作策略 | 複雜度判定→派發策略 | SBM-GATE §4 |
| ② 行動序列 | `<task>` 執行順序+依賴 | G1 `<task>` |
| ③ 驗收流程 | 明確化 `<complete>` 當輪清單 | SBM-TM-G2 §4 格式 |
| ④ 變更預案 | Minor/Major 預期風險 | SBM-GATE §5 |

本檔只寫當輪最新 `<plan>`，禁跨輪累積敘事；歸檔以 git 歷史為權威。

## 2. Minor/Major 變更模型（權威在 SBM-GATE §5）

執行中變更分兩類，路由細節見 SBM-GATE §5：

- **Minor**（當前 `<nnn>`）：順序/驗證/細節調整。commit `change(<slug>): <摘>`。
- **Major**（新 `<nnn>`）：目標/完成標準/架構改變。重新正反收斂 + 新 `<plan>`。

## 3. 邊界

- 計畫方向/技術選型歸 G1/G2 正反收斂。
- G3 不參與正反收斂。
- PASS/FAIL 歸 slug 層級由老闆。
