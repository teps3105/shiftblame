# SBM-TM-G2 — 內部技術實作視角

## 1. 範圍

G2 為內部技術實作視角的正反收斂軌，與 G1 外部研究規劃視角分軌進行。正方由主 session 擔任（身份切換），反方由子代理獨立對抗。側重將方案落地為可實作碼與測試，仍保留外部查證能力（與 G1 共業）。正反收斂完成後，實作交執行者承接。規範詞彙依 SBM-SKILL §3.1。讀寫中文 MUST 使用 UTF-8。

## 2. 正方：技術提案

### 2.1 核心職責

| 項目 | 內容 |
|------|------|
| ① 技術方案 | 對應 G1 變更清單每項 MUST 提出具體實作方式。技術選型 MUST 可追溯 G1 的 What/Why，SHOULD 優先既有技術棧，引入新依賴 MUST 說明必要性。MUST 遵循最短解決策階梯（§2.2） |
| ② 測試方案 | GWT 格式（§2.3） |
| ③ 實作驗證 | 遇缺陷 MUST 建立假設→驗證鏈，MUST 逐環驗證後再下結論。根因修復 SHOULD 優先於症狀修補 |
| ④ 證據責任 | MUST 標示來源／查證狀態／未知項／風險反證／替代方案。LLM 印象歸類為待查假設，MUST 經查證方推動 |

### 2.2 最短解決策階梯

依序評估，前一階可用即採用：

1. 需求存疑 → 先跳過（YAGNI）
2. 復用既有
3. 標準庫
4. 平台原生
5. 已裝依賴
6. 一行勝五十行
7. 投機抽象（單一實作的介面/工廠/設定）→ SHOULD 改以直接實作替代
8. 刪除 SHOULD 優先於新增

### 2.3 證據加權

依問題性質加權：

- 專案現況與租約界定邊界
- 官方文件
- 可重現實測
- 業界範例校準

LLM 既有知識僅作待查假設。

**觸發外部查證**：新依賴／版本／外部 API、法規安全效能成本、repo 無先例、與老闆直覺或既有架構衝突、agent 不確定。

### 2.4 GWT 測試骨架

```
T<N>: 標題
  Given: 前置條件
  When: 觸發動作
  Then: 預期結果
  預期紅燈: 實作前應失敗的具體表現
```

每個 G1 變更清單項目 MUST 至少一測試。

**測試先行（紅燈→綠燈）**：實作前 MUST 先寫測試。測試結構 MUST 按專案特性建立正確結構（框架依專案技術棧與可驗證性質選擇測試形態）。MUST 涵蓋正常與異常路徑。紅燈 MUST 具體可觀察。

**測試層次**：

| 層次 | 存放 |
|------|------|
| 單元／整合／端到端／回歸 | 主 repo |
| 探索性 | `.shiftblame/tmp/` |

## 3. 反方：技術質疑

聚焦「技術品質」。計畫方向審查歸 G1 反方職權。

質疑方向：

- 測試涵蓋度
- 技術方案合理性（是否引入不必要複雜度）
- 過度工程審查（可否刪減、投機抽象、重複標準庫/平台能力）
- 程式碼品質
- 提交規範（範圍限於 G1 變更清單）
- 技術債
- 跨檔一致性
- GWT 格式合規
- 證據充分性
- 反迎合檢查
- 查證觸發

### 3.1 標註格式

`D[N] [HIGH/MEDIUM/LOW]：質疑摘要`

| 等級 | 定義 |
|------|------|
| HIGH | 技術缺陷／測試嚴重遺漏／與 G1 衝突 |
| MEDIUM | 覆蓋不足／可改善設計 |
| LOW | 建議改善 |

結論段落 MUST 彙整風險清單 + 建議方向。

## 4. 越權防線（路由出口）

### 4.1 計畫方向路由

計畫方向與需求合理性審查歸 G1 反方職權。G2 遇此 MUST 轉交 G1。

### 4.2 PASS/FAIL 路由

PASS/FAIL 決策歸 slug 層級由老闆（`<nnn>` 無閘門）。

### 4.3 產出路由

反方專司質疑，產出 MUST 回傳管理者。遇寫檔需求 MUST 限於白名單 G1.md+G2.md。方案設計歸正方職權。

## 5. 收斂：技術實作

### 5.1 流程

由管理者執行，綜合正方方案與反方質疑，產出 G2 視角技術結論：

1. 質疑逐項回應（承認／反駁／部分承認／記入技術債／提醒接受）
2. 測試階段（紅燈）
3. 實作階段（綠燈）
4. 重構（可選）
5. 驗證結果

### 5.2 收斂產出

收斂 MUST 產出 `<complete>`（完成標準序列）供執行者對照達成。與 G1 `<task>` 合併為執行者實作基線。

### 5.3 明確化 `<complete>`

實作前規劃階段產出，MUST 附於當輪 G2.md 末尾。將抽象 `<complete>` 細化為機械驗證清單。

**格式**：`T[N]`（與 G1 `<task>` 同軌）下掛 `- [ ] V[N][.M] 驗證類型：判準`

**驗證類型限四類**（源自執行者自驗手段）：

- grep
- 行數
- 字串
- 檔案

**不可機械驗證項**（語義／行為）MUST 標 `S[N]`「需管理者初審」，MUST 歸入 S# 類別。

明確化段為抽象 `<complete>` 的細化；抽象段仍為權威。
