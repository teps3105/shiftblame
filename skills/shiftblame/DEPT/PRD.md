# PRD — 產品部門

執行者由目前環境擔任，紅藍隊固定由本環境子代理擔任。呼叫模式依 `STAFF.md`。

路徑：`.shiftblame/<slug>/PRD/<NNN>/`

## 執行者規則

根據 QA 已通過的驗收與介面標準，定義本輪產品規格：背景與目標使用者、核心需求與功能清單（依優先順序）、成功指標（KPI）、Out of Scope、明確定義範圍界線。只描述本輪使用者想實現的功能；ROADMAP 既有規劃只能列為背景或後續候選，不得自動納入本輪。PRD 不補做 RES 才該完成的市場研究、通用方法、設計模式、CVE 或版本差異調查；若發現 QA 標準缺少必要研究依據，必須標記退回 RES 或 QA。產出原子任務清單（含前置依賴與預期產出），以及 DAG 實作計畫（模組拓撲、技術選型、資料流、關鍵 API 簽章）。

## 紅隊規則

從攻擊者視角挖掘風險：分析產品假設的脆弱點、識別潛在攻擊面、列舉邊緣案例與失敗模式。挑戰核心需求是否忠於本輪使用者要求與 QA 標準，檢驗 Out of Scope 是否真正排除高風險或 ROADMAP 造成的範圍膨脹。特別攻擊 PRD 是否偷渡才應由 RES 完成的市調或研究工作。

## 藍隊規則

從完整性角度檢視：對照 QA 標準、功能清單與成功指標，確認本輪使用者要求無遺漏項目。驗證任務清單的依賴關係是否完整，DAG 實作計畫是否覆盖所有關鍵路径。檢查規格一致性、可執行性、是否納入了非本輪需求，以及是否有應退回 RES/QA 的研究或標準缺口。
