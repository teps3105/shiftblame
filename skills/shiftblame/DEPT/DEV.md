# DEV — 開發部門

執行者由目前環境擔任，紅藍隊固定由本環境子代理擔任。呼叫模式依 `STAFF.md`。

路徑：`.shiftblame/<slug>/DEV/<NNN>/`

## 執行者規則

DEV 開始前，管理者必須先詢問老闆想先達成 PRD 裡的哪個可見功能；若尚未取得選擇，不得開始實作。DEV task.md 的目標必須用繁體中文描述本回合要實際做出的作品效果，不得只寫技術項目。

依老闆選定的可見功能實作，內部可參考 PRD 的技術選型、資料流與實作計畫，但對老闆回報時只說作品變化與可操作結果。每完成一個可觀看片段，實際啟動作品並提供 URL、指令、截圖或操作證據；老闆可在 DEV 中多次要求觀看變化、追加小調整或指定下一個想看到的效果。這些 `BossPreview` 回合不需要紅藍隊，但必須把已完成、已驗證、待調整事項記錄到 `result.md`。

實作時保留必要工程品質：先定義可驗證行為，再完成程式碼與測試；完成前執行語法檢查、測試或等效驗證。驗證結果回報給老闆時，使用「可以新增並看見卡片」「按下儲存後資料還在」這類功能語言，不用測試框架或技術術語包裝。

## 紅隊規則

驗證老闆選定的可見功能是否真的做出來：檢查使用者能否按預期操作、看到結果、遇到錯誤時理解發生什麼。攻擊邊界情境（空內容、極端值、特殊字元、快速連點、刷新或重開）。技術缺陷可記錄，但紅隊結論必須先用作品語言說明哪個使用情境會失敗。

## 藍隊規則

確認本回合功能完整性：對照老闆選定的 PRD 功能與 DEV task.md 的可見功能，確認作品是否能被操作、觀看與驗證。整理紅隊指出的使用情境，逐項判定已修正、可接受或必須退回。藍隊報告必須包含給老闆看的中文摘要：目前能看到什麼、怎麼試、還有哪些不符合期待。
