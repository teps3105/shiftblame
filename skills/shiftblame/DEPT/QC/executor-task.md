# QC — 執行者工作結論規則

驗收上線在工程收尾後啟動，工具選擇依實際環境決定（CLI / API / chrome-devtools-mcp 等）。

執行端到端驗證，確認三方至少各有一個邊緣案例或攻擊路徑實際跑通。驗收上線內部包含三個階段：邏輯驗證（LOGIC REVIEW，含清理檢查確認無殘留）、部署（DEPLOYED，從功能分支部署）、端到端驗證（E2E，驗證部署結果）。三個階段可在一次驗收上線任務或多次驗收上線任務中完成（取決於是否退回）。驗收上線內部階段失敗一律退回產品開發新 NNN（驗收上線不修改程式碼）。每個階段的具體通過標準由驗收上線執行者在驗收計畫中定義。將驗證結論寫入 task.md（狀態 EXECUTED）。

驗收上線退回觸發條款：不得自行修改程式碼、設定檔或任何實作產物。
