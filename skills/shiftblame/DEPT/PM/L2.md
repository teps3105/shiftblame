# PM — 執行者產出規則

依已確認的宣告，將研究調查與前端設計結論產出為 result.md，以目標導向描述工作成果。不得另建同名產物檔替代 result.md。

PM 是前端設計的唯一權威。產出的「前端設計與視覺規格」段落為前端所有設計決策的最終來源，DEV 不得自行決定前端設計，只能依此規格實作前端接線與資源管理。

## 前端設計產物暫存規則

前端設計的視覺產出（線框圖、互動原型、視覺稿、設計稿等）一律存放在 `.shiftblame/tmp/` 或 Open-design 環境的專案中，不進入版本控制。除非老闆明確要求納入版本控制，否則這些產物只作為開發中的參考材料。

PM result.md 中的文字形式設計規格（色值、間距、元件清單、互動流程描述等）為正式產物，必須完整寫入 result.md。

## 前端設計工具

PM 執行者在產出前端設計與視覺規格時，依老闆之 Open-design 環境操作，使用 MCP 工具或 HTTP API 進行前端設計與視覺驗證，讓老闆在專案中查看設計。

## 前端設計與視覺規格段落的內容結構

「前端設計與視覺規格」段落包含兩類內容：

- **設計規格**（文字形式，直接寫入 Markdown）：色彩系統（具體色值）、間距規範（具體數值）、字型規格、元件清單與規格、互動流程描述、響應式斷點定義等。這些內容必須足夠具體，讓 QA 能據此建立 Given/When/Then 設計驗證標準與 GWT 測試案例、讓 DEV 能據此實作前端接線。
- **設計稿**（視覺產出，暫存不進版本控制）：線框圖、互動原型、視覺稿等。依老闆之 Open-design 環境操作，產物存放在 `.shiftblame/tmp/` 或 Open-design 專案中讓老闆直接查看。除非老闆明確要求，不進入版本控制。

這些工具僅供 PM 階段使用，產出的設計成果直接寫入 result.md 的「前端設計與視覺規格」段落（文字規格部分）。設計成果必須足夠具體，讓 QA 能據此建立驗證標準與 GWT 測試案例、讓 DEV 能據此實作前端接線。

## 通用規則

result.md 必須 self-contained：完整寫入前輪仍然有效的結論，已被修正的以修正後版本呈現，禁止引用其他文件（如「如前輪所述」「見 XX/NNN」）。

ROADMAP 只能列為收尾後的穩定背景或後續候選，不得把 ROADMAP 既有規劃擴張成本輪需求，也不得把本輪流程待辦寫入 ROADMAP。

PM 可參照 `.shiftblame/PRD/` 中的產品需求文件作為需求來源（若存在）。PRD 為非強制參照。

PM 在 RAPID 模式下吸收 QA 職責（品質定義、測試標準、驗收條件），一併寫入 result.md。
