# PM — 執行者產出規則

依已確認的宣告，將研究調查與前端設計結論產出為 result.md，包含四段：需求釐清、市場研究、產品規格、前端設計與視覺規格。不得建立「需求釐清.md」、「市場研究.md」、「產品規格.md」或「前端設計與視覺規格.md」；四段都必須寫在同一份 result.md。

## 前端設計工具

PM 執行者在產出前端設計與視覺規格時，可使用以下工具：

- **`open-design`**（MCP 工具）：用於建立 UI/UX 設計，包含線框圖、互動原型、視覺稿、元件規格等。`open-design` 產出的設計稿可透過其內建預覽功能在瀏覽器中呈現。

- **`devtools-mcp`**（MCP 工具）：用於瀏覽器端視覺驗證。操作流程：（1）由 `open-design` 在瀏覽器中開啟設計稿預覽畫面；（2）透過 `devtools-mcp` 連接到該瀏覽器頁面；（3）使用 MCP 工具控制瀏覽器進行視覺驗證（檢查響應式佈局、驗證視覺一致性、確認互動行為）。不得匯出至本地臨時目錄做離線檢視。

## 前端設計與視覺規格段落的內容結構

「前端設計與視覺規格」段落包含兩類內容：

- **設計規格**（文字形式，直接寫入 Markdown）：色彩系統（具體色值）、間距規範（具體數值）、字型規格、元件清單與規格、互動流程描述、響應式斷點定義等。這些內容必須足夠具體，讓 QA 能據此建立 Given/When/Then 設計驗證標準、讓 DEV 能據此實作。
- **設計稿**（視覺產出，透過 `open-design` 工具整合）：線框圖、互動原型、視覺稿等。透過 `open-design` 的 Markdown 整合能力或工具內嵌機制呈現於 result.md 中。

這些工具僅供 PM 階段使用，產出的設計成果直接寫入 result.md 的「前端設計與視覺規格」段落。設計成果必須足夠具體，讓 QA 能據此建立設計驗證標準、讓 DEV 能據此實作。

## 通用規則

result.md 必須 self-contained：完整寫入前輪仍然有效的結論，已被修正的以修正後版本呈現，禁止引用其他文件（如「如前輪所述」「見 XX/NNN」）。

ROADMAP 只能列為收尾後的穩定背景或後續候選，不得把 ROADMAP 既有規劃擴張成本輪需求，也不得把本輪流程待辦寫入 ROADMAP。
