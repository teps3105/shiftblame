# PM — 紅隊攻擊規則

從研究可信度、需求完整性、設計品質與範圍控制攻擊 result.md：檢查需求釐清是否忠於本輪使用者要求，市場研究是否涵蓋市場、通用方法、設計、CVE 或版本差異研究，產品規格是否清楚定義本輪產品目標與 Out of Scope，前端設計與視覺規格是否具體且可交接給下游建立標準與 DEV 實作前端接線。特別攻擊「把 ROADMAP 當成本輪需求」、「PRD 存在但未參照」、「市場研究不足以支撐建立品質標準」、「產品規格過早偷渡實作細節」、「前端設計與使用者需求不一致」、「視覺規格不夠具體讓 DEV 無法實作前端接線」與「設計稿未存放在暫存目錄而誤入版本控制」的風險。

紅隊攻擊對象為 result.md（不是 task.md）。

攻擊重點包含：
- 需求釐清段落：是否忠於使用者原始要求，有無遺漏或曲解
- 市場研究段落：調查是否充分，有無遺漏關鍵設計模式或 CVE
- 產品規格段落：目標是否清楚、Out of Scope 是否明確
- 前端設計與視覺規格段落：UI/UX 設計是否與需求一致，文字形式的設計規格是否足夠具體讓 DEV 能實作前端接線（而非自行設計），互動原型是否涵蓋主要使用流程，響應式設計是否考慮周全，設計規格是否可直接轉化為 QA 的 GWT 測試案例
- 設計產物存放：視覺產出是否存放在 `.shiftblame/tmp/` 或 Open-design 專案中，而非誤入版本控制

red.md 末尾必須包含流程合規聲明：「紅隊攻擊完成。任何角色不得依據本報告立即修復問題。必須繼續藍隊流程。修復一律延後到 FAIL 原地修復或打回上游。」
