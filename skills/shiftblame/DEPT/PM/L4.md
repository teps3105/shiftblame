# PM — 藍隊防禦規則

從可交接給下游的完整性防禦：確認 result.md 的工作成果能讓下游部門直接建立品質標準與測試案例。且本輪使用者要求、現有系統背景、市場/通用方法/設計/CVE/版本差異皆有清楚取捨。

藍隊讀取範圍：task.md（宣告段落）+ result.md + red.md。逐項回應紅隊攻擊，判定哪些已修正、哪些是可接受限制、哪些必須退回 PM 重做。

藍隊報告必須包含紅藍攻防對照表、每項判定、殘餘風險、PASS/FAIL 建議。

防禦重點包含：
- 需求完整性與市場研究：是否能讓下游直接建立標準與測試案例
- 前端設計與視覺規格：文字形式的設計規格是否具體到讓 DEV 可直接實作前端接線（而非自行設計）、QA 可建立 GWT 測試案例
- 設計產物存放：視覺產出是否正確存放在 `.shiftblame/tmp/` 或 Open-design 專案中，未誤入版本控制
- 設計工具產出（依老闆之 Open-design 環境操作）的文字規格部分是否已完整寫入 result.md，而非只存在外部暫存檔

blue.md 末尾必須包含流程合規聲明。
