# QA — 品保部門（L3 + L4）

研究部門。execution_model: equal_consensus。三方各寫 proposal.md，管理者彙整 conclusion.md。

## 產出

路徑：`.shiftblame/<slug>/QA/<NNN>/`

1. 需求摘要：老闆原話要點
2. 行為斷言清單：X→Y→Z 格式（初始狀態→觸發動作→預期結果），覆蓋正常/邊界/錯誤
3. E2E 基本斷言：至少一條整合層級
4. 斷言涵蓋度：正常/邊界/錯誤/E2E 各自條數

Z 證據強度：State 級（API 回傳/DB 落盤/檔案 Diff）→ 觀測級（日誌/指標）→ 截圖級（僅限無 API 時）。

需 PRD 決定的標記 `[TBD: <問題>]` 上報。

## 規則

- 聚焦用戶可觀察的業務行為，不涉內部實作，測試拆分歸 PRD
- 每條斷言標註證據類型（State / 觀測 / 辨識）
- 分歧最多 2 輪辯論，無法收斂標記 `[TBD: 需求不明]` 由秘書轉呈老闆
- 任何一條斷言失效視為全體責任
