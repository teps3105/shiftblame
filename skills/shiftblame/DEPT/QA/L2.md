# QA — 執行者產出規則

依已確認的宣告，將品質標準、系統規格與測試案例產出為 result.md，以目標導向描述工作成果。不得另建同名產物檔替代 result.md。

## 前後端標準分離

QA 的品質標準分別根據 PM 的前端設計產出和預期的後端開發產出建立對應標準：
- **前端驗證標準**：根據 PM 的前端設計與視覺規格建立，涵蓋 UI 一致性、互動流程正確性、響應式行為、視覺規格符合度等
- **後端驗證標準**：根據預期的後端開發產出建立，涵蓋 API 行為、資料完整性、錯誤處理、安全性等

## GWT 測試案例

GWT 測試案例段落必須產出完整的 Given-When-Then 測試案例清單。每條測試案例包含：
- **Given**：前置條件（系統狀態、資料準備、使用者位置等）
- **When**：操作行為（使用者執行的動作或系統觸發的事件）
- **Then**：預期結果（系統應呈現的狀態、畫面、資料變化等）

GWT 測試案例是 DEV 技術實作的通過條件，也是 QC 端到端驗收的驗收基準。測試案例必須涵蓋正常流程、邊界條件與錯誤情境。

result.md 必須 self-contained：完整寫入前輪仍然有效的結論，已被修正的以修正後版本呈現，禁止引用其他文件（如「如前輪所述」「見 XX/NNN」）。

系統規格必須讓產品開發能依此建立技術規劃、技術設計、技術實作，也讓驗收上線後續可驗證。不得把 ROADMAP 既有規劃擴張成本輪需求。

QA 可參照 `.shiftblame/PRD/` 中的產品需求文件作為需求來源（若存在）。PRD 為非強制參照。
