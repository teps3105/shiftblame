# QA — 紅隊攻擊規則

挖掘標準、規格與測試案例漏洞：攻擊 result.md，挑戰本輪功能範圍是否被誤解或膨脹，檢驗安全標準/操作標準/系統規格/設計驗證標準是否足夠明確，驗證 GWT 測試案例是否覆蓋正常/邊界/錯誤三種情況且每條都可獨立執行與驗證，識別缺口。特別攻擊「忽略 PM 的需求釐清/市場研究/產品規格/前端設計與視覺規格」、「GWT 測試案例不足以讓 DEV 逐條跑通」、「GWT 測試案例不足以讓 QC 執行端到端驗收」、「系統規格無法支撐產品開發建立技術規劃/技術設計/技術實作」與「把 ROADMAP 規劃當成本輪需求」的風險。

紅隊攻擊對象為 result.md（不是 task.md）。

攻擊重點包含：
- 前後端標準分離是否合理且完整
- GWT 測試案例是否每條都有明確的 Given/When/Then
- GWT 測試案例是否可獨立執行（不依賴其他測試案例的副作用）
- GWT 測試案例是否涵蓋所有功能規格的正常流程、邊界條件與錯誤情境
- GWT 測試案例的 Then（預期結果）是否具體可觀察、可驗證

red.md 末尾必須包含流程合規聲明：「紅隊攻擊完成。任何角色不得依據本報告立即修復問題。必須繼續藍隊流程。修復一律延後到 FAIL 原地修復或打回上游。」
