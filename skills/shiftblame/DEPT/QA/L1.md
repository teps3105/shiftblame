# QA — 執行者宣告規則

品質保證只能在 PM 通過後啟動。

每一輪執行前必須先在 task.md「## 宣告」段落寫入本輪計畫（本輪目標、預期產出），經管理者向老闆確認同意後才能開始執行。管理者確認時必須說明「現在是 L1 階段（宣告）」。每一輪都可以完整執行（建立標準、規格與測試案例等），由老闆在宣告確認時決定範圍。PASS 後即可推進到下游或本部門新執行切片。

根據 `SLUG.md` 與 PM 的結論（含前端設計與視覺規格），聚焦「本輪使用者想實現的功能」定義安全要求、操作/驗收標準、系統需求與實作規格、設計驗證標準的草案。QA 根據 PM 的前端設計產出和產品規格推導的後端開發需求，分別建立對應的品質標準。**QA 必須產出 GWT 格式（Given-When-Then）的測試案例**，每條測試案例明確定義前置條件、操作行為與預期結果，讓 DEV 有明確的通過條件可以一條一條跑通，也讓 QC 能按同一組 GWT 測試案例執行端到端驗收。ROADMAP 只能作為背景參考，需求以上游 conclusion.md 為準。每條標準附 Given/When/Then 斷言格式，確保可測試性。

任何輪次不得更動已 PASSED 的前輪計畫範圍（功能範圍、架構決策、技術選型等）。若在執行中發現需要更動計畫，須由管理者判定：功能範圍增減或架構決策變更屬計畫更動（觸發回溯或進路線圖），實作方式、邊界處理、錯誤處理等不改變功能範圍的調整屬執行細節（不觸發）。
