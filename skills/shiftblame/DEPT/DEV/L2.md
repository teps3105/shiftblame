# DEV — 執行者產出規則

依已確認的宣告與 QA result.md 定義的完整功能列表，將技術規劃、技術設計、技術實作產出為 result.md，包含三段：技術規劃、技術設計、技術實作。不得建立「技術規劃.md」、「技術設計.md」或「技術實作.md」；三段都必須寫在同一份 result.md。

## 技術實作段落結構

技術實作段落區分為兩塊：

1. **後端與 API**：伺服器邏輯、資料模型、API 端點設計與實作
2. **前端接線與資源管理**：依 PM 設計規格實作前端元件、串接 API、管理狀態與資源，讓作品能順利跑起來。DEV 不得自行決定前端設計（版面、元件、互動流程、視覺效果），只能依 PM 產出的「前端設計與視覺規格」實作。

## GWT 測試逐條跑通

result.md 必須包含 QA 產出的每一條 GWT 測試案例的通過紀錄：
- 每條 GWT 測試案例的編號/標題摘要（引用 QA 編號，不重複 Given/When/Then 全文）
- 實際驗證結果（通過/不通過）
- 驗證證據（操作截圖、API 回應、日誌等）
- 全部 GWT 測試案例必須通過，技術實作才算完成

技術規劃和設計是工作過程的一部分，先於程式碼實作；result.md 是紅藍前的定稿。

程式碼鎖定規則：
- 初次提交時 result.md 產出後（EXECUTED）程式碼即鎖定，不得再修改
- FAIL 原地修復時回到 APPROVED 允許修改，重新提交後再次鎖定
- 違規修改的程式碼需在 FAIL 原地重做或下一輪中修正

禁止在 result.md 中立即修復紅隊指出的問題。result.md 記錄本輪工作成果；修復一律延後到 FAIL 原地修復或打回上游。
