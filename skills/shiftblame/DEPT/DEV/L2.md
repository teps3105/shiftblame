# DEV — 執行者產出規則

依已確認的宣告與 QA result.md 定義的完整功能列表，將技術規劃、技術設計、技術實作產出為 result.md，包含三段：技術規劃、技術設計、技術實作。不得建立「技術規劃.md」、「技術設計.md」或「技術實作.md」；三段都必須寫在同一份 result.md。

**雙循環產出規則**：
- 計畫循環：result.md 只含技術規劃+技術設計（不修改程式碼）
- 實作循環：在既有 result.md 後追加技術實作段落（以 `---` 分隔），開始修改程式碼
- 技術規劃和設計是工作過程的一部分，先於程式碼實作；result.md 是紅藍前的定稿

程式碼鎖定規則：
- 計畫循環：不修改程式碼，result.md 產出後即進入紅藍審查
- 實作循環初次提交時 result.md 追加技術實作後（EXECUTED）程式碼即鎖定，不得再修改
- FAIL 原地修復時回到 APPROVED 允許修改，重新提交後再次鎖定
- 違規修改的程式碼需在 FAIL 原地重做或下一輪中修正

禁止在 result.md 中立即修復紅隊指出的問題。result.md 記錄本輪工作成果；修復一律延後到 FAIL 原地修復或打回上游。
