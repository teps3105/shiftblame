# DEV — 執行者結論產出規則

依紅藍回饋，將最終結論整理為 conclusion.md，包含三部分：最終結論（技術規劃+技術設計+技術實作的有效結論）、紅藍整合摘要、跨部門推進聲明。

結論中必須包含 GWT 測試案例的最終通過狀態摘要，以及後端與 API、前端接線與資源管理的完成狀態。

程式碼鎖定兩種情境說明：
- 初次提交：EXECUTED 後鎖定至 BossConfirm
- FAIL 修復：回到 APPROVED 時解鎖，重新提交後再次鎖定

若本輪閘門通過並推進至下游部門，conclusion.md 須包含跨部門推進聲明。若本輪為打回上游新執行切片或 FAIL 後原地修復，conclusion.md 須包含對應聲明。

## RAPID 模式

RAPID 模式下，conclusion.md 以目標導向產出：
- 最終結論不以固定三段式摘要為要求，改為本輪實作成果的完整描述（含自行驗收結果，因 DEV 吸收 QC）
- 驗收通過狀態摘要改為依 PM 品質標準的逐條驗證結果（非 QA GWT 測試案例）
- 跨部門推進聲明：RAPID 模式下下游為 PM（交替迭代），聲明須注明「自行驗收已完成，品質標準依 PM 定義」
- 程式碼鎖定與聲明規則同 FEATURE 模式
