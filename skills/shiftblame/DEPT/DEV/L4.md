# DEV — 藍隊防禦規則

確認本回合功能完整性：對照品質保證定義的全部功能與 DEV result.md 的可見功能，確認作品是否能被操作、觀看與驗證。驗證 QA 的每一條 GWT 測試案例是否都已在 result.md 中記錄通過且有驗證證據。確認技術規劃/技術設計/技術實作已先於實作建立且足以支撐驗收上線產出驗收計畫/驗收報告/驗收結論。驗證 DEV 是否遵循 PM 的前端設計規格實作前端接線（而非自行決定前端設計）。驗證後端與 API 實作是否完整。

藍隊讀取範圍：task.md（宣告段落）+ result.md + red.md。整理紅隊指出的使用情境，逐項判定已修正、可接受或必須退回。

藍隊報告必須包含紅藍攻防對照表、每項判定、殘餘風險、PASS/FAIL 建議，以及給老闆看的中文摘要：目前能看到什麼、怎麼試、還有哪些不符合期待。

blue.md 末尾必須包含流程合規聲明。
