# GATE — 閘門、狀態機與收尾

1. **回饋即意圖**：老闆回饋為意圖確認素材，不可直接執行，禁止寫入記憶
2. **SOP 紀律**：可更新 SOP 作為全局標準，建立與修改皆需意圖揭露
3. **PRD/PID 筆記本**：老闆的筆記本，agent 可參考與協助整理，不進 slug 鏈
4. **先提出再質疑**：正方提出→反方質疑，四出口各正→反→收斂三輪辯論
5. **迭代收斂**：閘門 FAIL 以收斂產出為起始基線重跑（增量更新不重建）

## 狀態機

```
        →入口閘門FAIL→ 回意圖揭露步驟重新與老闆溝通確認
PLANNED → DEVELOPED → VERIFIED → PROSPECTED → PASSED
 (計畫)    (開發)      (驗收)      (展望)
  ↓FAIL      ↓FAIL       ↓FAIL      ↓FAIL
PLANNED   DEVELOPED   VERIFIED     PROSPECTED
```

| 狀態 | 入口閘門（意圖揭露） | 出口閘門（老闆確認） |
|------|----------------------|----------------------|
| PLANNED | — | G1 計畫出口 |
| DEVELOPED | G2 開發入口 | G2 開發出口 |
| VERIFIED | G3 驗收入口 | G3 驗收出口 |
| PROSPECTED | G4 展望入口 | G4 展望出口 |
| PASSED | 全部通過 | — |

PASS→入口閘門→下行為。VERIFIED→PROSPECTED 為 G3 PASS 後自動進入。L0 前檢視 SLUG.md。

## 閘門紀律

**四出口各雙閘門**：每出口含入口閘門（意圖揭露）＋出口閘門（老闆確認），通過才進下行為。
**入口 FAIL**：回 MANAGE.md 觸發流程第 3 步（呈現意圖→與老闆溝通確認），非出口 FAIL。
**出口 FAIL**：以收斂產出為起始基線重跑，增量更新不重建。
**反方定位**：質疑正方論點不做決策，禁止使用 PASS/FAIL。
**租約延續**：出口閘門通過後，管理者主動確保下一閘門入口重新載入技能定義檔（短期租約續約）。G3→G4 自動進入時，管理者於展望調度前主動重新載入（見 MANAGE.md 步驟 7、SKILL.md 步驟 4）。
**老闆回溯權**：老闆隨時可回到前閘門重跑（正→反→收斂），commit 在收尾前非最終。

## G4 閘門決策語義
| 決策 | 語義 | 後續行為 |
|------|------|----------|
| 收尾 | 展望完成 | 確認→合併→推送→清理→歸檔→更新四文件 |
| 開新 NNN | 展望建議需更進一步修正 | 同 slug 開新 NNN，從計畫行為重跑 |
| FAIL | 展望未收斂 | 以收斂產出為起始基線重跑 |
**技術債阻塞**：H 級未處理不可開新 slug（收尾除外）。M/L 不阻塞但記錄暫緩理由。三終態見 ROLE/G4.md。
**遞迴保護**：同 slug 連續技術債 NNN 上限 3 輪（不含功能 NNN）。超過強制收尾，殘餘債轉 ROADMAP.md。G3 判品質，G4 判方向，均由未來的老闆決定。「開新 NNN」不代表推翻驗收結論。

## 收尾

- **NNN=Commit**：每 NNN 恰好一個 commit；G3 出口閘門 PASS 後管理者執行。同 slug 用 `feat/<slug>` 分支，G4 收尾才合併回 main。收尾流程：確認→合併回 main→推送→清理分支→清理 `.shiftblame/tmp/`→歸檔→更新四文件
- **main 保護**：agent 禁止操作 main。歸檔完成後管理者輸出結束提示訊息
