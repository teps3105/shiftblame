# GATE — 閘門與收尾

## 閘門原則

1. **回饋即意圖**：老闆每次說話即觸發意圖揭露，管理者必須先揭露理解到的意圖，確認後才執行
2. **SOP 約束**：可更新 SOP 作為全局標準，建立與修改皆需意圖揭露
3. **先提案再質疑**：G1/G2 雙軌平行，各走正→反→收斂流程
4. **迭代收斂**：管理者以最後收斂為基線增量增加
5. **雙軌平行**：G1 計畫視角 ‖ G2 技術視角，同時進行，各自收斂
6. **多子代理多視角**：G1/G2 正方/反方皆使用多子代理進行多觀點作業

## 狀態序

Slug：IN_PROGRESS → PASSED

每個 NNN：CONVERGED → PASSED（commit）或 FAILED（開新 NNN）

FAIL 以收斂為基線增量增加（正→反→收斂重新跑）。

## NNN 生命週期

**START**：載入三層租約（SOP｜SLUG §7｜SKILL+GATE+MANAGE+ROLE/G1+G2）→揭露目標→**暫停等老闆確認**。

**正方（平行）**：G1 正方提出計畫方案 ‖ G2 正方提出技術方案。

**反方（平行）**：G1 反方質疑計畫方案 ‖ G2 反方質疑技術方案。

**收斂**：管理者分別收斂 G1 和 G2，產出兩份各自結論。反方 H/M/L 標註，不做決策。收斂後揭露實作意圖（將做什麼變更）→**暫停等老闆確認**→確認後才正式實作。

**閘門**：呈現雙軌收斂結論→老闆 PASS/FAIL。

- PASS → 按兩份收斂結論實作 → commit
- FAIL → 以收斂為基線增量增加 → 開新 NNN

## 收尾

1. 最終 NNN PASS 後實作完成
2. 管理者品質確認
3. 老闆 PASSED
4. 管理者提交文件更新
5. 合併→推送→清理
6. 歸檔至 `.shiftblame/archive/`

**回歸規則**：改善建議→SOP 未完成項目；BUG→ROADMAP 已知問題；下一步→ROADMAP 後續計畫。
