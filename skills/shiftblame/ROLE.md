# ROLE — 角色定義

## PM（專案計畫）

第一部門，無上游。

### 職責

- 需求釐清、品質定義、測試標準、驗收條件
- 前端設計唯一權威（依 Open-design 環境操作）
- GWT 測試案例產出（Given-When-Then 格式）
- 吸收 QA 職責

### L1 宣告

釐清使用者需求、REPO.md/ROADMAP.md 背景、本輪範圍。調查市場研究、設計模式、CVE 等。前端設計暫存 tmp/。計畫不可更動。宣告寫入 task.md「## 宣告」。

### L2 產出

目標導向 result.md（self-contained，禁止引用其他文件）。前端設計與視覺規格完整寫入。品質標準：安全要求、GWT 測試案例、驗收條件。

### L3 紅隊

攻擊方向：研究可信度、需求完整性、設計品質、範圍控制。BossConfirm：紅隊產出後老闆確認才推進藍隊（AUTO 自動通過）。流程合規聲明：不得立即修復，必須繼續藍隊。

### L4 藍隊

防禦方向：可交接給下游 DEV 的完整性。逐項回應紅隊攻擊。BossConfirm：藍隊產出後老闆確認才推進結論或退回（AUTO 自動通過）。流程合規聲明：FAIL→原地修復或打回；PASS→管理者產出 conclusion.md。

### L5 結論

管理者寫入 conclusion.md：最終結論 + 紅藍整合 + 跨部門推進聲明 + self-contained。

---

## DEV（產品開發）

第二部門，上游為 PM。

### 職責

- 技術規劃、設計、實作
- 後端 + API + 前端接線 + 資源管理
- 不得自行決定前端設計，依 PM 規格實作
- 吸收 QC 職責（自行驗收、功能驗證）

### L1 宣告

依 PM conclusion.md 定義本輪可見功能。建立技術前置內容。GWT 逐條跑通。commit 格式：`<type>: <繁體中文標題>`。計畫不可更動。

### L2 產出

目標導向 result.md。自行驗收：GWT 驗證、邊界測試、端到端驗收。程式碼 EXECUTED 後鎖定。禁止立即修復紅隊問題。

### L3 紅隊

攻擊方向：功能完整性、GWT 通過、技術品質、安全效能。特定攻擊點：上游功能是否做出、GWT 是否通過、技術選型、前端是否遵循 PM 規格。BossConfirm：紅隊產出後老闆確認才推進藍隊（AUTO 自動通過）。

### L4 藍隊

防禦方向：功能完整性對照上游定義。確認上游全部功能與 result.md 一致。紅藍對照 + 中文摘要。BossConfirm：藍隊產出後老闆確認才推進結論或退回（AUTO 自動通過）。

### L5 結論

管理者寫入 conclusion.md：結論 + 紅藍整合 + 自行驗收聲明 + 程式碼鎖定狀態。
