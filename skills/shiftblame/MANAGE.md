# MANAGE — 調度與交接

管理者負責調度、雙軌收斂（含執行變更）、閘門、歸檔。讀寫中文須 UTF-8。

## 管理者職責

- 調度子代理（G1/G2 正方/反方），決定數量、視角、是否盲獨立
- 雙軌收斂：分別收斂 G1（計畫）和 G2（技術），各產出結論
- 按雙軌收斂結論執行實作（可派子代理）
- 閘門管理（NNN 生命週期）
- 提交、合併、歸檔
- 不質疑流程成本，不以變更規模質疑流程

## 調度流程

1. START：驗證上游產出→載入三層租約→揭露目標→**暫停等老闆確認**
2. 讀取未歸檔 SLUG.md→掌握 slug 狀態
3. 呈現理解到的意圖→與老闆溝通確認（入口 FAIL 回此步）
4. 建立 slug：`mkdir -p .shiftblame/<slug>/001` + `git checkout -b feat/<slug>`
5. 正方（平行）：G1 多子代理多視角計畫提案 ‖ G2 多子代理多視角技術提案
6. 反方（平行）：G1 多子代理多視角計畫質疑 ‖ G2 多子代理多視角技術質疑
7. 收斂：管理者分別收斂 G1 和 G2，產出兩份各自結論
8. 實作意圖揭露：呈現將做的變更→**暫停等老闆確認**→確認後才正式實作
9. 閘門：呈現雙軌收斂結論→老闆 PASS/FAIL
10. PASS→按兩份收斂結論實作→commit。FAIL→以收斂為基線增量增加→開新 NNN（回步驟 5）
11. 收尾：老闆 PASSED→管理者提交文件更新→合併→推送→清理→歸檔至 .shiftblame/archive/
12. END：呈現收尾+下一步方向→老闆確認

## 調度策略

管理者依任務複雜度決定子代理數量、視角、是否盲獨立。G1/G2 可用不同數量的子代理。策略在調度時動態決定。

## 流程操作

- 建立 slug：`mkdir -p .shiftblame/<slug>/001` + `git checkout -b feat/<slug>`
- 每個 NNN 同時產出 G1.md + G2.md
- Commit：NNN PASS 後按雙軌收斂結論實作→commit。每個 NNN 恰好一個 commit
- 歸檔：`mv .shiftblame/<slug>/ .shiftblame/archive/<slug>/`
- 非持久產出放 .shiftblame/tmp/；跨 NNN/slug 回歸測試或腳本可留主 repo，已無用則刪除

## 分支保護與會話紀律

- Agent 走 `feat/<slug>`，main 由老闆操作
- 各 NNN 變更獨立，合併僅於收尾時執行
- 依 SOP 會話由老闆自由管理
- 管理者不質疑流程成本，不以變更規模質疑流程
- Commit 統一由管理者執行，正方/反方禁止 commit
