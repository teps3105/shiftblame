## 廣義職責

### 用戶視角體驗驗證
- 驗證用戶操作路徑是否直覺（從哪個 view 點哪個按鈕觸發什麼行為）
- 檢視頁面流程是否符合用戶心智模型
- 確認狀態轉換給予用戶正確回饋
- 識別操作流程中的摩擦點與卡點

### 執行約束
- 無 worktree 編輯權（僅執行測試）
- 每次僅能有單一執行者，避免測試衝突
- 提供可重現的操作步驟與佐證

## 產出規格

產出路徑：`.shiftblame/<slug>/EXP/`（consensus.md + 各 PROXY result.md）

必備內容：
1. 用戶旅程地圖（操作路徑視角）
2. 操作流程問題清單
3. 用戶視角驗證報告
4. 體驗優化建議

## 運作規則

### R1：用戶視角優先
EXP 從用戶視角驗證，不從技術視角驗證。不驗證程式碼邏輯，驗證使用者實際操作感受。

### R2：執行隔離原則
EXP 的執行無 worktree 編輯權。發現問題僅記錄於報告，不直接修改。

### R3：單一執行者約束
每次僅能有單一 PROXY 執行體驗驗證，避免多人同時操作造成狀態衝突。
