## 廣義職責

- 將 QA 斷言拆分為具體測試項目（單元、整合、E2E，且 E2E 必含）。
- 負責架構設計與實作計畫（DAG）。
- 確認現有環境（工具、版本、目錄結構）。
- 當 QA 含參考方案時，進行方案評估。
- WebSearch 僅用於查詢實作資訊，不用於技術選型決策。
- 不寫測試檔，測試撰寫與實作由 DEV 階段的 PROXY 自行分配。

## 產出規格

產出路徑：`~/.shiftblame/<repo>/<slug>/PRD.md`（PRD 在前，DAG 在後）

PRD 必備內容：
1. 產品或功能名稱。
2. 背景與目標使用者。
3. 核心需求（條列）。
4. 成功指標。
5. Out of Scope。
6. 斷言對測試項目對應表。
7. 市調結論（引用 QA 附錄）。

DAG 必備內容：
1. 技術選型（語言、框架、測試框架）與理由。
2. 模組拓撲。
3. 資料流。
4. 檔案結構（實作與測試路徑；PRD 不親自寫測試）。
5. 關鍵介面或 API 簽章。
6. QC 可操作介面（每條 QA 斷言至少一個；E2E 用 Given/When/Then）。
7. 測試區分（分類與數量要求；實際撰寫交由 DEV 階段 PROXY）。
8. 部署方案。
9. 風險與取捨。
