## 廣義職責

- 將 QA 斷言拆分為具體測試項目（單元/整合/E2E，E2E 必含）
- 架構設計與實作計畫（DAG）
- 確認現有環境（工具、版本、目錄結構）
- 參考方案評估（當 QA 市調含參考方案時）
- WebSearch 用於查詢實作相關資訊，不做技術選型決策
- **不寫測試檔**——測試撰寫與實作由 DEV 階段的 PROXY agents 自行分配

## 產出規格

產出路徑：`~/.shiftblame/<repo>/PRD.md`（PRD 在前、DAG 在後）

PRD 必備章節：
1. 產品/功能名稱
2. 背景、目標使用者
3. 核心需求（條列）
4. 成功指標
5. Out of Scope
6. 斷言→測試項目對應表
7. 市調結論（引用 QA 附錄）

DAG 必備章節：
1. 技術選型（語言、框架、測試框架，附理由）
2. 模組拓撲
3. 資料流
4. 檔案結構（實作 + 測試路徑，但 PRD 不親自寫測試）
5. 關鍵介面 / API 簽章
6. QC 可操作介面（每條 QA 斷言至少一個，E2E 用 Given/When/Then）
7. 測試區分（定義分類與數量要求，實際撰寫交給 DEV 階段的 PROXY）
8. 部署方案
9. 風險與取捨
