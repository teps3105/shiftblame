# sb-go — 三權自動推進並放行開發（輕量自動模式）

當使用者要求「三權自動跑」「自動產 G1 G2 G3」「sb-go」時執行本 prompt。用於非 loop 模式下，秘書翻譯完意圖後，老闆授權讓 G1／G2／G3 自動推進並放行開發。是 §11「每階段須顯式觸發」原則的**輕量例外授權模式**，也是「全程手動」與「sb-loop 全 slug 自主」之間的中間點——授權後自動連續觸發既有指令，非跳過各指令流程。

先 `load skill: shiftblame`，確認前置（非 loop 模式、意圖已翻譯、當前在三權制衡），再執行：

## 流程

SECRETARY 依序自動調用對應指令推進，期間**使用指令顯式觸發各階段**（每階段仍走完整流程）：

1. **sb-req**：以 AUDITOR 角色子代理產出 G1（需求／驗收）。
2. **sb-meth**：以 RESEARCHER 角色子代理產出 G2（技術），承接 G1。
3. **sb-plan**：以 DEVELOPER 角色子代理產出 G3（計畫），依 G1 寫驗收再依 G2 寫步驟。
4. **§10 一致性核對**：SECRETARY 親自核對三對六向；不一致要求對應角色子代理調整後重核。
5. **sb-do**：核對通過 → 放行進入開發。SLUG §3 節點推進到 `開發`。

**停止點**：進入開發後，sb-go 到此為止。後續由老闆手動：
- 開發完成 → sb-review 收斂。
- 開發途中方向錯誤 → sb-req／sb-meth／sb-plan 退回對應權。

## 邊界

- sb-go 是**輕量自動模式**：只自動「三權產出＋放行開發」（單次 nnn 前半），不自主開發／收斂／開新 nnn（那是 sb-loop）。
- 各階段仍走完整流程（含外部獨立研究、§10 核對）；「自動」指免逐階段手動輸入，非免遵守制衡規範。
- §10 核對不通過時停止，回報老闆具體缺漏，不自主修補。
- 進入開發後停止；若要全 slug 自主，改用 sb-loop。
