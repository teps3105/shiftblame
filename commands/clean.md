# /clean — 環境清理指令

## 觸發策略

| 觸發者 | 條件 |
|--------|------|
| 老闆 | 隨時 |
| agents | 隨時 |

統一授權原則：clean 不涉及閘門狀態推進，老闆與 agents 均可觸發。

## 自動觸發時機

- 管理者執行 Result Check 時同步觸發（DEV/QC result.md 已寫入，管理者檢查流程中一併 clean）
- G3 歸檔前
- 功能分支 merge 後
- 老闆隨時手動 `/clean`

## 行為

掃描下列四類：

1. **部署垃圾**：build artifact、暫存檔、多餘產物
2. **測試垃圾**：coverage report、log、截圖、錄影、下載檔
3. **殭屍依賴**：未使用的套件、過期依賴
4. **背景程序**：殘留 dev server、watcher、測試服務

產出清理報告，列出發現項目與建議處置。

## 安全限制

- 只報告不執行：掃描後產出報告，不自動刪除任何檔案
- 不刪除 git 追蹤檔案：僅處理未追蹤的垃圾檔案
- 老闆確認後才清理：報告交由老闆確認，確認後才執行清理
- 不清理 `.git` / `.shiftblame`

## 定位

clean 為收尾檢查清單中可自動掃描的子集。完整收尾仍需管理者手動確認。
