載入 `shiftblame` skill。本指令用於**非 loop 模式**下，SECRETARY 翻譯完意圖後，老闆授權讓 G1／G2／G3 三權自動推進並放行開發。是「一般模式（全程手動）」與「`/sb-loop`（全 slug 自主）」之間的**輕量自動模式**——自動跑三權產出＋放行，到進入開發後停止，後續由老闆手動觸發。

## 前置條件

| 條件 | 判定 |
|------|------|
| 非 loop 模式 | 當前 `<nnn>` 無 loop 授權（否則用 `/sb-loop`） |
| 秘書已翻譯意圖 | §2 意圖揭露已完成（原始命題、意圖翻譯、邊界、候選方案已分開） |
| 當前在三權制衡階段 | SLUG §3 節點為 `三權制衡（G1↔G2↔G3）` |

任一未滿足 → 提示老闆先完成前置（翻譯意圖、或該用 sb-loop）。

## 觸發後流程

SECRETARY 依序自動調用對應指令推進，期間**使用指令顯式觸發各階段**（每階段仍走對應指令的完整流程，非跳過）：

1. **`/sb-req`**：以 AUDITOR 角色子代理產出 G1（需求／驗收）。
2. **`/sb-meth`**：以 RESEARCHER 角色子代理產出 G2（技術），承接 G1。
3. **`/sb-plan`**：以 DEVELOPER 角色子代理產出 G3（計畫），依 G1 寫驗收再依 G2 寫步驟。
4. **§10 一致性核對**：SECRETARY 親自核對三對六向；不一致要求對應角色子代理調整後重核。
5. **`/sb-do`**：核對通過 → 放行進入開發。SLUG §3 節點推進到 `開發`。

**停止點**：進入開發後，sb-go 到此為止。後續由老闆手動：
- 開發完成 → `/sb-review` 收斂。
- 開發途中方向錯誤 → `/sb-req`／`/sb-meth`／`/sb-plan` 退回對應權。

## 邊界

- sb-go 是**輕量自動模式**：只自動「三權產出＋放行開發」（單次 nnn 的前半），不自主開發、不自主收斂、不自主開新 nnn（那是 `/sb-loop`）。
- 各階段仍走對應指令的完整流程（含外部獨立研究、§10 核對）；「自動」指免老闆逐階段手動輸入指令，非免遵守制衡規範。
- §10 核對不通過時停止，回報老闆具體缺漏，不自主修補。
- 進入開發後停止；若老闆要全 slug 自主，改用 `/sb-loop`（需重新評估前置）。
