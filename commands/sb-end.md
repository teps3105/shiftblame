載入 `shiftblame` skill。本指令用於結束當前 `<slug>`——老闆主動呼叫即表達結束意圖，對應 SBM-SKILL §2 的 PASS checkpoint 與 §6「結束 `<slug>`」路由。

## 觸發後流程

### 1. 嚴格檢查 PASS 前置條件（SBM-SKILL §2）

逐項核對，**任一未滿足即停止並提示老闆**，不執行收尾：

| 前置條件 | 判定 |
|----------|------|
| 當前 `<nnn>` 三者重審通過 | §6 三權制衡與重審 |
| 輕量保鮮完成（§1.7.1） | SLUG 技術債／臨時租約已寫回 |
| 證據完整 | G3 行為證據齊全 |
| 無未驗項 | AUDITOR 無「未驗」標記；應跑 e2e 皆已跑 |

任一未滿足 → 提示老闆具體缺項，建議先收斂當前 nnn（或用 `/sb-req` 回 G1）後再結束。

### 2. 前置通過 → 執行完整收尾保鮮（SBM-SKILL §1.7.2）

前置全數通過後，SECRETARY 執行收尾（既定維護動作，不需另行授權）：

1. SLUG `status` 改為 `passed`。
2. 從當下 codebase、設定、測試入口重寫 `SOP.md`；保留仍成立的配置與規範，刪除已取代或無法查核者。
3. 重新整理 `ROADMAP.md`：移除已完成項，部分完成者改寫為剩餘方向；不得藉保鮮新增未授權需求。
4. 依 SOP 盤點測試資產；探索性內容留 `.shiftblame/tmp/`。
5. 依分支政策合併、推送與清理。
6. 將 `.shiftblame/<slug>/` 移至 `archive/`。

## 邊界

- 老闆呼叫本指令即為結束意圖（PASS 授權）；但**品質門檻不可繞過**——前置條件未滿時拒絕收尾。
- 收尾僅限當前 `<slug>`；不影響其他已歸檔 slug。
- 新增產品目標、改變產品邊界或把剩餘方向擴張成新需求，仍須老闆明確授權，不藉收尾保鮮偷渡。
