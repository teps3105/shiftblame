# /fail — 閘門失敗指令

## 觸發策略

| 觸發者 | 條件 |
|--------|------|
| 老闆 | 任何閘門狀態，無前置條件 |
| agents | result.md 必須已存在 |

統一授權原則：agents 可觸發不涉及閘門狀態向前推進的指令。fail 可回溯/退回，不推進閘門。

## 前置條件（僅限 agents）

- agents 自動觸發 fail 前必須驗證 result.md 存在
- 老闆手動觸發不受此限
- 沒有 result.md 的 agents fail = 假 fail，拒絕執行

## 判斷觸發者

- 使用者在對話中直接輸入 `/fail` → 老闆觸發
- 管理者依流程自動執行 → agents 觸發

## 老闆手動路徑

1. 根據當前閘門狀態，執行下方自檢清單對應分組的項目
2. 發現違規 → 回溯（同 NNN 內）或退回（跨 NNN）
3. 無違規 → 詢問老闆「哪邊 fail 了？」

## agents 自動路徑

1. 驗證 result.md 存在 → 不存在則拒絕（假 fail）
2. 讀取 result.md 中的回溯/退回方向
3. 有方向 → 直接執行回溯或退回
4. 無方向 → 回報老闆請求指示
5. 向老闆回報回溯/退回原因

## 自檢清單

根據當前閘門狀態，只執行該狀態對應欄位標記 ✓ 的項目。

| # | 自檢項目 | EXECUTED | RED | BLUE | RESULT/CHECKED |
|---|---------|:--------:|:---:|:----:|:--------------:|
| 1 | task.md 存在且含 YAML frontmatter | ✓ | ✓ | ✓ | ✓ |
| 2 | EXECUTED 後無額外 commit（DEV） | ✓ | ✓ | ✓ | ✓ |
| 3 | 狀態序列是否經過 RED | — | ✓ | ✓ | ✓ |
| 4 | 紅隊後無 commit | — | ✓ | ✓ | ✓ |
| 5 | 並行紅藍隊 | — | — | ✓ | ✓ |
| 6 | 藍隊後無 commit | — | — | ✓ | ✓ |
| 7 | 紅藍隊期間工作目錄鎖定 | — | ✓ | ✓ | ✓ |
| 8 | 退回後沿用舊 red.md/blue.md | — | ✓ | ✓ | ✓ |
| 9 | 紅藍隊由子代理執行 | — | ✓ | ✓ | ✓ |
| 10 | result.md 未修復紅隊問題 | — | — | — | ✓ |
| 11 | 狀態序列經過 CHECKED | — | — | — | ✓ |

自檢發現違規時：
- 同 NNN 內的流程問題 → 回溯至違規點重新執行
- 跨 NNN 的問題 → 退回建立 NNN+1 修正
